# RISKS - 成本库风险和确认项台账

更新时间：2026-06-21

用途：集中管理业务确认项、内网部署风险和数据口径风险。凡是不确定但会影响实现、验收、上线或后续维护的事项，都应在这里留痕。

| D-011 | Redis 未启动或连接配置不一致 | 可能导致中台缓存、登录态或框架能力异常，进而影响成本库启动或请求 | 本地 Redis 使用 `127.0.0.1:6379`，成本库正式数据不存 Redis | 启动前检查 Redis；内网确认 Redis 地址、库号、密码策略 | 持续关注 |

## 工程与质量风险

| 编号 | 风险/确认项 | 影响 | 当前默认假设 | 处理动作 | 状态 |
|---|---|---|---|---|---|
| E-001 | 自定义 SQL 的租户/数据权限风险 | 聚合接口可能越权或跨租户查数 | MyBatis Plus 租户拦截器和数据权限拦截器会处理自定义 SQL，但子查询和聚合 SQL 仍需实测 | 用非 admin、不同租户、不同部门用户验证 `@Select` 聚合接口；必要时显式补 tenant/data permission 条件或调整 Mapper | 【需验证】 |
| E-002 | 聚合 SQL 索引风险 | 内网真实数据量下待分配池、预警中心、总体展示响应变慢 | MVP 先用现有表和外网小数据验证功能 | 内网导入真实数据前检查 `project_code`、`work_order_no`、`domain_code`、`unit_name`、`stage_code`、`deleted`、`tenant_id` 等组合索引 | 观察中 |
| E-003 | 预警状态重复记录风险 | 同一工作令可能出现多条推送/处理状态，导致预警列表重复或状态不稳定 | 业务操作按 `warning_source + project_id + work_order_id` 只维护一条状态记录 | 后续考虑增加唯一约束或在写入前强校验重复记录 | 【需确认】 |

| E-009 | 菜单权限与静态路由不一致风险 | 内网可能出现有页面无接口权限、有菜单无按钮或静态路由绕过菜单控制 | 开发期使用静态路由，正式环境依赖中台菜单和权限点 | 内网联调时按角色逐页验证菜单、按钮、接口和数据权限，必要时收敛静态入口 | 【需验证】 |
| E-010 | 敏感信息泄露风险 | 数据库账号、Nacos 账号或内网配置被误提交、打包或分享 | 敏感信息集中记录在部署文档，便于本地接手和内网迁移 | 分享、提交、归档前检查敏感信息；公网仓库和外发材料必须脱敏 | 持续关注 |
| E-011 | 监控和慢 SQL 可观测性不足 | 内网真实数据下接口变慢或导入失败时定位困难 | MVP 先通过本地日志和手动 SQL 验证排障 | 后续补接口耗时、慢 SQL、导入失败原因统计和关键接口调用量监控 | 观察中 |

- 新风险进入本文，不只写在聊天记录里。
- 已确认的业务口径同步更新 PRD、数据模型、接口文档或部署手册。
- 风险状态可用：【需确认】、【需验证】、处理中、观察中、已关闭、持续关注。
