# 三项修复本地验收（2026-09-10 晚间）

- 当前后端源码与已审查测试副本的 173 个 Java 文件哈希一致。

- PG17 重跑 103 项通过，失败/错误/跳过均为 0；日志：仓库根 .preview/acceptance-20260910-pg17.log。
- PG9.2.23 重跑专项 12 项通过，失败/错误/跳过均为 0；日志：仓库根 .preview/acceptance-20260910-pg92.log。
- 专项包含 17 个实体实际 Mapper 插入/回读/回滚，四类首次角色授权、12 种切换、撤销重授、三类范围保存、并发、失败回滚与租户边界。外部身份仍用测试替身，数据库是真实隔离 PostgreSQL。
- 完整及备用 SQL 在两版 PG 的新建独立审查库各复验 11 组场景，通过；见 acceptance-sql-matrix.json。

PG9.2 初次复跑因宿主机 55492 无端口映射而失败，未进入数据库测试。仅切换隔离容器，在 PG17 测试结束后使用空闲的 55417 端口重跑，已明确核对服务版本为 PostgreSQL 9.2.23。没有把连接失败计为业务测试通过。

## 2. 真实前端页面与修复

实际访问用户已启动的 http://localhost，使用既有 cost1 测试账号登录；没有模拟首页接口。前端为实际源码 Vite 服务。

发现：原 3D 顶部 aggregateMetrics 仍调用 buildOverviewMetrics，虽然院内到账字段已加入 aggregateDomain，但展示使用总到账 49,150，收益率显示 43%；经典页院内到账 43,670、收益率 48%。

修复：顶部改调用 buildInternalOverviewMetrics，展示院内标签和院内金额；收益率仍为院内账面/院内到账，公式没有改动。新增测试直接验证最终 aggregateMetrics，避免只验证中间汇总对象。前端现为 15 项通过，成本模块类型检查通过。

实际页面对照（万元）：

|领域|院内合同|院内到账|院内账面|收益率|
|---|---:|---:|---:|---:|
|运载火箭|25,300|18,440|11,530|63%|
|导弹武器|9,600|7,150|4,080|57%|
|卫星项目|16,300|12,660|4,680|37%|

经典页与 3D 顶部院内合计现一致：到款率 74.52%，执行率 36%。平台舱四个领域金额与上述数据一致。总合同 66,260、总到账 49,150 是另一组明确标为总额的指标，不能与院内指标混用。

首页只显示四个正式领域；目录树中仍可见演示领域，说明源数据存在 DEMO，而首页筛选已生效。没有删除 DEMO 数据或缩小目录树授权范围。

经典页、3D、平台舱共 12 次逐领域实际点击均通过，目标一致：/cost/catalog?domainCode=LAUNCH、MISSILE、SATELLITE、SPACE；每次均确认目录页对应领域标题和项目结果。3D 默认自动动效，实际 WebGL 火箭模型可见；平台舱可在单舱和四舱间切换。
