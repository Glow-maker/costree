# 待分配池页面设计

更新时间：2026-06-03

## 1. 页面目标

`/cost/pending-allocation` 用于集中展示产品简称未填或填写为 `待分配` 的工作令，让业务人员快速看到待分配规模、涉及单位、账面支出和超支情况。

本页面是前台展示和穿透模块，不改变工作令基础信息的 `status`，也不新增汇总表。

## 2. 业务规则

待分配判定：

- `productShortName` 为 `NULL`；
- 或去空格后为空字符串；
- 或值等于 `待分配`。

账面成本展示口径：

- 优先使用 `cost_work_order_ledger_detail` 按工作令聚合出的 `ledgerBookCostAmount`；
- 无账面明细时使用 `cost_work_order.book_cost_amount` 兜底；
- 超支第一版沿用 10% 阈值。

## 3. 路由和入口

| 项 | 内容 |
|---|---|
| 路由 | `/cost/pending-allocation` |
| 页面文件 | `src/views/cost/pendingAllocation/index.vue` |
| 顶部入口 | `CostPortalHeader` 新增“待分配池” |
| 权限 | 第一版复用工作令查询权限；是否拆独立权限点【需确认】 |

## 4. 页面结构

页面保持业务中台风格，采用紧凑筛选、指标、表格和抽屉穿透，不做大屏或营销式卡片。

主要区域：

| 区域 | 内容 |
|---|---|
| 顶部 | 复用 `CostPortalHeader` |
| 指标区 | 待分配工作令数、涉及单位数、账面成本合计、超支数量 |
| 筛选区 | 关键词、领域、系列、型号、项目、阶段、所属单位 |
| 单位汇总区 | 按单位展示待分配数量、账面成本、超支数量，可点击穿透 |
| 主表格 | 分页展示待分配工作令明细 |
| 抽屉 | 点击单位后展示该单位下待分配工作令支出明细 |

## 5. 接口调用

| 场景 | 接口 | 说明 |
|---|---|---|
| 指标和单位汇总 | `GET /cost/work-order/pending-allocation/summary` | 当前筛选范围下汇总，不一次性拉取明细 |
| 主表格 | `GET /cost/work-order/pending-allocation/unit-detail` | `unitName` 为空时查询全部待分配工作令，后端分页 |
| 单位抽屉 | `GET /cost/work-order/pending-allocation/unit-detail` | 带 `unitName` 查询该单位工作令，后端分页 |
| 筛选项目范围 | `GET /cost/project/page` | 前端按领域/系列/型号/项目换算 `projectCodes` |

## 6. 分页策略

- 主表格使用后端分页，默认每页 10 条。
- 单位抽屉使用后端分页，默认每页 10 条。
- 不在前端一次性加载全部待分配工作令。
- 筛选条件变化后，主表格和抽屉都回到第一页。

## 7. 空状态和异常状态

- 无待分配工作令时，指标为 0，表格显示空状态。
- 单位汇总为空时，不展示伪造单位数据。
- 接口异常时使用中台消息提示，不在页面保留假数据。
