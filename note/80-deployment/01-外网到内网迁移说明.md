# 外网到内网迁移与部署用户手册

状态：持续维护  
最后更新：2026-05-22  
适用阶段：成本库 MVP，嵌入已有数据中台  

## 1. 手册目标

本文记录成本库从外网测试环境迁移到内网数据中台时，需要人工检查、修改、执行和确认的事项。

当前成本库不是独立系统，内网部署时应嵌入已有数据中台：

- 前端：合入数据中台 Vue3 前端。
- 后端：以 `cost-server` 独立服务方式部署。
- 网关：通过 `gateway-server` 转发 `/admin-api/cost/**`。
- 登录、租户、权限、菜单、组织、消息等能力优先复用已有数据中台。

## 1.1 先理解 Nacos、Redis 和网关

成本库本地和内网部署都不是“前端直接访问某个 Java 端口”。

嵌入业务中台时，请求链路是：

```text
前端页面 /cost/...
  -> 网关 /admin-api/cost/**
  -> Nacos 查找 cost-server 实例
  -> cost-server
  -> MySQL
```

Nacos 的关键作用是服务注册/发现：`cost-server` 启动后把自己的服务名、地址和端口注册进去，网关再通过服务名 `cost-server` 转发请求。如果 Nacos 里没有该实例，网关会返回 `Unable to find instance for cost-server`。

Redis 的关键作用是缓存和中台基础设施，不保存成本库正式业务数据。成本项目、工作令、账面明细等正式数据仍以 MySQL 为准。

本地 `jt` profile 当前口径：

| 组件 | 当前值 | 作用 |
|---|---|---|
| gateway-server | `127.0.0.1:38080` | 前端统一接口入口 |
| cost-server | `127.0.0.1:38108` | 成本库后端服务 |
| Nacos | `127.0.0.1:8848` | 服务注册/发现 |
| Redis | `127.0.0.1:6379` | 缓存和平台基础设施 |

账号、密码和外网测试库连接只维护在 `80-deployment/00-环境账号与敏感信息.md`。

## 3. 内网部署总流程

1. 确认内网 MySQL、Redis、Nacos、网关、system-server、infra-server 可用。
2. 在内网 MySQL 创建成本库 schema。
3. 执行 `schema-mvp.sql` 创建成本库 MVP 表。
4. 配置 `cost-server` 连接内网 MySQL、Redis、Nacos。
5. 确认 `cost-server` 注册到 Nacos，服务名为 `cost-server`。
6. 确认 `gateway-server` 已有 `/admin-api/cost/**` 路由。
7. 合并/部署前端成本库页面。
8. 在中台菜单和角色权限中配置成本库菜单、按钮权限、数据权限。
9. 启动并验证健康检查、列表查询、导入模板、导入、导出。
10. 只在测试库需要模拟数据时执行 `seed-mvp.sql`；真实环境不要执行清空灌数脚本。

## 4. MySQL 准备

### 4.1 数据库要求

| 项 | 要求 |
|---|---|
| MySQL 版本 | 建议 MySQL 8.x；如使用 5.7 需实测兼容【需确认】 |
| 字符集 | `utf8mb4` |
| 排序规则 | `utf8mb4_unicode_ci` |
| 存储引擎 | InnoDB |
| 时区 | 建议 `Asia/Shanghai` |
| 账号权限 | 需要目标 schema 的建表、索引、增删改查权限 |
| schema 名称 | MVP 默认 `costree_mvp`，如内网改名必须同步修改后端 JDBC URL |

### 4.2 建库建表

内网可直接执行：

```powershell
mysql -h <内网MySQL地址> -P 3306 -u <用户名> -p < H:\light\project\costree\note\30-data\schema-mvp.sql
```

如果在内网机器上没有这个盘符路径，就把 `schema-mvp.sql` 拷贝到内网机器后执行：

```bash
mysql -h <内网MySQL地址> -P 3306 -u <用户名> -p < /path/to/schema-mvp.sql
```

`schema-mvp.sql` 本身包含：

```sql
CREATE DATABASE IF NOT EXISTS `costree_mvp`
  DEFAULT CHARACTER SET utf8mb4
  DEFAULT COLLATE utf8mb4_unicode_ci;

USE `costree_mvp`;
```

如果内网 DBA 要求使用已有 schema，先修改 `schema-mvp.sql` 里的数据库名，再执行【需确认】。

### 4.3 当前 MVP 表清单

| 表名 | 用途 | 关键约束 |
|---|---|---|
| `cost_source_project_tree` | 源主业项目树 | `tenant_id + source_project_id` 唯一 |
| `cost_model_node` | 领域-系列-型号三级树 | `tenant_id + node_code` 唯一 |
| `cost_project` | 主业项目锚定信息 | `tenant_id + project_code` 唯一 |
| `cost_unit_dict` | 单位字典 | `tenant_id + accounting_unit_code` 唯一，用于院内/院外分类 |
| `cost_project_basic` | 项目基本情况 | 通过 `project_id` 关联主业项目 |
| `cost_work_order` | 工作令基础信息 | `tenant_id + work_order_no` 唯一 |
| `cost_work_order_project_ref` | 工作令关联主业项目字典 | `tenant_id + source_work_order_id` 唯一 |
| `cost_work_order_ledger_detail` | 工作令账面成本凭证明细 | `tenant_id + source_detail_id` 唯一 |
| `cost_unit_cost_detail` | 成本结构明细 | `tenant_id + project_code + stage_code + unit_name` 唯一 |
| `cost_import_batch` | 导入批次 | 记录导入类型、成功失败数量 |
| `cost_import_error` | 导入错误明细 | 通过 `batch_id` 关联导入批次 |
| `cost_warning_record` | 超支预警记录 | 记录目标成本、实际成本、超支比例、推送状态 |

### 4.4 表结构要求

这些字段和类型不要随意改：

- 所有表保留 `creator`、`create_time`、`updater`、`update_time`、`deleted`、`tenant_id`。
- `deleted` 使用 `bit(1)`，配合 MyBatis-Plus 逻辑删除。
- 金额字段使用 `decimal(18,2)`，单位当前按“万元”处理。
- 比例字段使用 `decimal(8,4)`，例如 10% 存 `0.1000`。
- `tenant_id` 必须和内网中台租户编号一致。
- `dept_id` 必须对应内网真实组织/部门 ID，用于数据权限。
- `owner_user_id` 必须对应内网真实用户 ID，用于后续负责人和消息推送。
- `cost_project.project_code`、`cost_work_order.work_order_no` 不能重复。
- `cost_unit_dict.inside_institute` 是成本树区分院内/院外单位的当前依据。
- `cost_unit_dict` 的真实来源需内网确认：成本库维护、湖仓同步或复用中台单位主数据【需确认】。
- `cost_source_project_tree`、`cost_work_order_project_ref`、`cost_work_order_ledger_detail` 是业务方参考后的源数据表，主要用于同步、追溯和后续聚合，不直接替代当前页面业务表。
- `cost_work_order_ledger_detail.amount` 当前按源系统金额保存，`amount_wan` 是展示折算字段；正式单位和借贷汇总口径需业务确认【需确认】。

### 4.5 测试数据脚本使用规则

`seed-mvp.sql` 会先清空以下表再灌入外网模拟数据：

```sql
DELETE FROM `cost_warning_record`;
DELETE FROM `cost_import_error`;
DELETE FROM `cost_import_batch`;
DELETE FROM `cost_unit_cost_detail`;
DELETE FROM `cost_work_order_ledger_detail`;
DELETE FROM `cost_work_order_project_ref`;
DELETE FROM `cost_work_order`;
DELETE FROM `cost_project_basic`;
DELETE FROM `cost_unit_dict`;
DELETE FROM `cost_project`;
DELETE FROM `cost_model_node`;
DELETE FROM `cost_source_project_tree`;
```

所以：

- 外网测试库可以重复执行 `seed-mvp.sql`。
- 内网测试库如需要演示数据，可以执行，但要先确认库里没有真实数据。
- 内网真实库不要执行 `seed-mvp.sql`。
- 内网真实数据应通过 Excel 导入、接口同步或业务维护页面进入【需确认真实数据来源】。

## 6. 网关配置

内网必须确保 `gateway-server` 有成本库路由。

当前代码已在：

```text
H:\light\project\sqlbot_with_bcback\baback\yudao-gateway\src\main\resources\application.yaml
```

增加：

```yaml
- id: cost-admin-api
  uri: grayLb://cost-server
  predicates:
    - Path=/admin-api/cost/**
  filters:
    - RewritePath=/admin-api/cost/v3/api-docs, /v3/api-docs
```

Knife4j 聚合也增加：

```yaml
- name: cost-server
  service-name: cost-server
  url: /admin-api/cost/v3/api-docs
```

如果内网网关配置也由 Nacos 管理，需要把同样配置同步到 `gateway-server-<profile>.yaml`【需确认】。

网关验证：

```bash
curl http://<gateway地址>:48080/admin-api/cost/project-basic/page?pageNo=1&pageSize=1 \
  -H "Authorization: Bearer <真实token>" \
  -H "tenant-id: <真实租户ID>"
```

期望返回：

```json
{"code":0,"data":{"list":[],"total":0},"msg":""}
```

如果返回 `code=404`，优先检查网关路由是否生效。

如果返回 `401`，优先检查登录 token、system-server、租户和权限。

### 7.2 内网构建注意

前端生产构建不会使用 Vite dev server 的本地代理，所以 `vite.config.ts` 里开发期 `/admin-api/cost` 代理不会进入生产运行链路。

内网应走真实网关：

- 同域部署：`VITE_BASE_URL=''`，`VITE_API_URL=/admin-api`。
- 前后端分域部署：`VITE_BASE_URL='http://<内网网关地址>:48080'`，`VITE_API_URL=/admin-api`。
- 独立 `cost-server` 调试才允许配置 `VITE_COST_BASE_URL='http://127.0.0.1:48108'` 和 `VITE_COST_MOCK_LOGIN=true`。


内网如果使用 `dev`、`test`、`stage` 等模式，确认对应 `.env.*` 的 `VITE_BASE_URL` 指向内网网关，不要保留外网演示地址或本机地址。

## 9. 内网首次数据初始化

### 9.1 空库上线

如果希望内网先空库上线：

1. 执行 `schema-mvp.sql`。
2. 不执行 `seed-mvp.sql`。
3. 使用页面或 Excel 导入真实项目数据。

### 9.2 内网测试演示数据

如果只是内网测试库演示：

1. 确认库里没有真实数据。
2. 执行 `schema-mvp.sql`。
3. 执行 `seed-mvp.sql`。
4. 登录前端查看项目基本情况、工作令列表、成本树详情页和单位详情页。

### 9.3 真实数据导入前需要确认

- 真实“领域-系列-型号”口径。
- 主业项目编号是否唯一。
- 工作令编号是否唯一。
- 单位字典是否由成本库维护，还是从中台/湖仓协作单位字典同步。
- 院内/院外分类是否以“是否八院内”为准。
- 源主业项目树是否以 `xmnm` 为稳定主键，增量同步是否以 `lastmodify` 为准。
- 工作令关联主业项目字典变更后，历史账面成本按原映射追溯还是按当前映射重算。
- 账面成本明细 `je` 的单位、借贷方向、冲销金额汇总规则。
- 承研单位、项目办、部门、用户 ID 的来源。

## 11. 常见问题

### 11.1 前端提示“访问资源不存在”

优先检查：

1. 请求 URL 是否为 `/admin-api/cost/...`。
2. 网关是否配置 `/admin-api/cost/**`。
3. `cost-server` 是否注册到 Nacos。
4. 如果是外网本地联调，是否重启了前端 dev server，使 Vite 代理配置生效。

### 11.1.1 网关提示 `Unable to find instance for cost-server`

这是网关无法从 Nacos 找到 `cost-server` 实例，不是 Vue 页面渲染问题。

优先检查：

1. `CostServerApplication` 是否已启动。
2. `GET http://127.0.0.1:38108/actuator/health` 是否返回 `UP`。
3. `cost-server` 是否使用 `jt` profile 或正确的内网 profile。
4. `spring.cloud.nacos.discovery.enabled` 是否为 `true`。
5. `cost-server` 与 `gateway-server` 的 Nacos 地址、namespace、group 是否一致。
6. 修改 YAML 后是否重启了 `CostServerApplication`。

如果 `38108` 健康检查正常，但经 `38080` 仍报该错误，优先看 Nacos 服务列表和网关路由配置。

### 11.2 前端提示“账号未登录”

内网环境：

- 检查登录 token。
- 检查 `system-server` 是否正常。
- 检查 `tenant-id` 是否正确。
- 检查用户是否有成本库菜单和按钮权限。

外网单服务联调：

- 需要走前端 Vite 代理，并显式配置 `VITE_COST_MOCK_LOGIN=true` 后才会由代理注入本地 `login-user`。
- 直接请求 `48108` 时需要手动带 `login-user` 请求头。

### 11.3 `cost-server` 连接数据库失败

检查：

- JDBC URL 是否指向内网 MySQL。
- schema 名是否存在。
- 用户名密码是否正确。
- MySQL 账号是否有目标 schema 权限。
- 网络、防火墙、白名单是否放通。
- `allowPublicKeyRetrieval=true` 是否保留。

### 11.4 网关返回 404

检查：

- `gateway-server` 是否加载了包含 `cost-admin-api` 的配置。
- 如果网关配置来自 Nacos，本地 `application.yaml` 的修改不会自动生效，必须同步到 Nacos。
- `cost-server` 服务名必须是 `cost-server`。

### 11.5 不要做的事

- 不要在真实库执行 `seed-mvp.sql`。
- 不要在内网正式环境开启 `COST_LOCAL_TEST_MOCK_PLATFORM=true`。
- 不要把外网测试库账号密码复用到内网。
- 不要只改前端代理来解决内网问题；内网必须走真实网关和服务发现。
- 不要绕过中台权限直接开放成本库接口。
