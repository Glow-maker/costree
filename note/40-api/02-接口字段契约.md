# 接口字段契约

当前本地授权字段见文末 [2026-09-08 增补](#local-auth-contract)；前面的历史 MVP 草案不作为本地授权接口契约。

状态：初稿

## 1. 目标

定义成本库 MVP 接口的请求参数、响应字段、字段类型、必填规则和错误场景。后续生成前端 `src/api/cost/...`、后端 Controller、ReqVO、RespVO、ExcelVO 时，以本文件为字段口径。

## 2. 通用约定

| 项 | 约定 |
|---|---|
| 数据库字段 | 使用 `snake_case`，以 `schema-mvp.sql` 为准 |
| 接口字段 | 使用 `camelCase`，便于 Vue3/TypeScript 使用 |
| 金额字段 | `BigDecimal` / `number`，单位暂定“万元”【需确认】 |
| 日期时间字段 | `LocalDateTime` / `string`，格式 `YYYY-MM-DD HH:mm:ss` |
| 研制周期字段 | `string`，格式 `YYYY-MM` |
| 分页响应 | 复用 Yudao `PageResult<T>`：`list`、`total` |
| 通用响应 | 复用 Yudao `CommonResult<T>`：`code`、`data`、`msg` |
| 删除 | MVP 走逻辑删除，表字段 `deleted` |
| 租户 | 表保留 `tenant_id`，外网测试统一使用 `124`，与本地代理 `VITE_COST_LOCAL_TENANT_ID` 保持一致 |

### 13.1 连接与通用响应

- `BASE_URL` 表示已经包含管理 API 前缀的环境入口，例如 `https://<网关域名>/admin-api`；实际网关若增加服务前缀或重写路径，应按现场路由设置，不能重复拼接 `/admin-api`。
- 认证沿用现有中台登录得到的 access token：`Authorization: Bearer <access_token>`；租户头为 `tenant-id: <当前授权租户编号>`。PUT 使用 `Content-Type: application/json`。租户头不是自行切换租户权限的凭证。
- 响应包装为 `{code, data, msg, traceId}`；成功 `code=0`、`msg=""`，写接口 `data=true`。`traceId` 随日志上下文生成，可能为空；空字段可能为 null 或被序列化配置省略，客户端不能要求所有可选字段必有值。
- Java Long 字段包括用户 ID、revision、roleRevision、scopeRevision。沿用当前客户端的数值传输，示例使用小整数；不要对真实长 ID 做有损转换。
- HTTP 状态与响应体 `code` 分开判断。Controller 的 CommonResult 错误可能通过 HTTP 200 返回，不能把 `code=403/500` 等同 HTTP 403/500，也不能仅看 HTTP 200 就认为成功。网关及认证过滤器可能另返回 HTTP 错误，真实环境需记录两者。

### 13.2 角色请求参数

| 接口 | 参数 | 类型 / 约束 | 说明 |
|---|---|---|---|
| page、scope-user-page | pageNo | Integer，默认 1，最小 1 | 页码 |
| page、scope-user-page | pageSize | Integer，默认 10，服务层限制 1–100 | 不支持 -1 全量；共享分页注解上限与服务上限不同，以本服务限制为准 |
| page、scope-user-page | username | String，可选 | trim 后按本地角色记录的 username 模糊筛选 |
| lookup | userId | Long，可选 | 大于 0 时优先按 ID 查找，忽略 name；否则走名称分支 |
| lookup | name | String，名称分支必填 | trim 后长度 2–64，调用旧中台名称匹配 RPC；匹配超过 100 条拒绝，返回前过滤停用账号、自己、管理员及专员 |
| assign | userId | Long，必填且大于 0 | 当前租户存在且启用的目标中台账号 |
| assign | roleCode | String，可空，原输入最长 64 | trim 后必须为四类角色之一；null、空串、全空白或未传均等同撤销。建议显式传 null，防止漏字段误撤销 |
| assign | revision | Long，必填且大于等于 0 | 使用最近读取的 UserVO.revision；没有本地记录时为 0，不能固定写 0 |

page 查询的是本地覆盖记录，不是全部中台用户；scope-user-page 在此前提下排除 roleCode 为 NULL 的撤销记录。未被本地接管的平台用户通过 lookup 查找。分页结果在 RPC 后过滤不存在/受保护账号，因此 `total` 是本地查询总数，可能大于可见 list 的数量；分页不保证只返回启用用户。

角色分配每次成功都会递增 revision 并追加审计，包括重复分配相同角色。角色发生有效变化或撤销时，清空该用户的领域、项目、单位范围；重复分配相同有效角色保留范围。没有本地记录时沿用平台角色及原菜单权限；存在本地记录后，成本模块使用本地业务角色及角色权限白名单。`roleCode=NULL` 是永久保留的显式撤销记录，不得删除后回退平台旧权限。

### 13.4 范围请求及选项

| 接口 | 参数 | 类型 / 约束 | 说明 |
|---|---|---|---|
| GET profile | userId | Long，必填 | 指定目标用户；服务层检查账号存在、启用及操作者权限 |
| PUT profile | userId | Long，非空 | 目标账号；不要把角色表主键作为 userId |
| PUT profile | scopeRevision | Long，服务端必填校验 | 必须使用 GET profile 返回的授权快照版本；角色或范围变更后旧值被拒绝，缺失也拒绝 |
| PUT profile | roleRevision | Long，VO 未标必填 | 有本地角色记录时必须与当前版本相等，null 也会冲突；无本地记录时当前实现不检查此值 |
| PUT profile | domainCodes | String[]，默认 [] | 授权领域编码；按角色规则使用 |
| PUT profile | projectCodes | String[]，默认 [] | 授权项目编码；按角色规则使用 |
| PUT profile | manageUnitCodes | String[]，默认 [] | 管理单位编码，不能传核算单位名称代替 |
| options | kind | String，必填 | 精确取值 domain / project / unit |
| options | keyword | String，可选 | domain：编码/名称模糊匹配；project：项目编码/名称模糊匹配；unit：当前忽略 |
| options | domainCode | String，可选 | 仅 project 生效，精确筛选领域 |
| options | projectCode | String，可选 | 仅 project 生效，模糊筛选项目编码 |

范围保存是整体替换，不是局部 PATCH。三个数组先移除空白、trim、去重、排序，再按目标角色重建；不使用的数组不会生成相应范围。校验失败抛异常时，事务回滚原范围的删除及写入。

领域和项目必须存在于当前租户成本数据中。管理单位必须在单位字典中启用（ENABLE）且为院内单位（insideInstitute=true）；保存时从字典取名称。项目办项目作有效性校验；研制单位不再保存手选项目，按当前租户工作令及单位成本记录的 unit_name 匹配有效字典中的核算单位名/管理单位名，动态获取关联项目。无有效单位或无关联项目时不授予业务访问权限。

options 返回 `data` 数组：domain 为 `{domainCode,domainName}`；project 为 `{projectCode,projectName,domainCode,domainName}`，最多 50 条；unit 为 `{manageUnitCode,manageUnitName}`，仅启用院内单位。domain/unit 当前没有分页或 50 条上限，不应自行假设与项目选项一致。

### 13.6 错误响应（当前实现）

| 场景 | 当前响应体 code / msg | 客户端处理 |
|---|---|---|
| 缺必填参数、Bean Validation 不通过 | 400；提示由具体校验器生成 | 修正参数；例如 assign 缺 revision、userId 非正数 |
| 无管理权限、混配专员、改自己角色、受保护目标、账号跨租户/不存在/停用 | 403 / 没有该操作权限 | 停止操作；不要依赖服务内部异常文本区分跨租户与不存在 |

| PUT profile 的本地角色版本不匹配 | 500 / 成本角色已发生变化，请重新选择用户后授权 | 重新查询档案、重新选择范围 |
| 名称关键字无效、匹配过多、pageSize 大于 100（但通过共享注解） | 500 / 对应参数提示 | 缩小查询；与 Bean Validation 400 区分 |

### 13.7 版本与并发限制

- `revision` 和 `roleRevision` 仍是角色版本；新增 `scopeRevision` 为角色与范围共用的授权快照版本。GET profile 读取前后校验该值；PUT profile 在用户锁内校验并递增，旧页面不得覆盖新范围。角色分配成功同样递增 scopeRevision。两种版本不得混用。
- R1 修复：编辑档案读取前后比较 scopeRevision；期间发生 cost 本地角色/范围提交，拒绝返回该不一致快照。外部中台角色变更不由 cost 锁控制，仍须在保存时复核身份并进行真实 RPC 验收。
- R2 修复：用户锁内比较 scopeRevision，成功保存时推进版本。两个专员持相同旧快照依次提交，第二次被拒绝，不能覆盖第一次保存的范围。
- 20260910 已通过服务层定向回归；真实 DWS/RPC 并发验收待执行。首次同时创建用户锁行时，唯一键冲突的一方事务失败并需刷新重试，不会静默覆盖。修复背景见 [授权并发审查](../90-logs/20260907-local-authorization-review.md)。

数据授权页可直接保存成本角色，再配置范围。角色变更或撤销仍清除原范围；全局查看和授权专员无需业务范围。GET profile 允许管理者查看同租户受保护账号身份；成本授权专员显示正确身份和说明，混配业务角色仍提示冲突。保存范围继续禁止专员修改自己、管理员和其他专员。

为兼容旧 system，复用 `AdminUserApi.listByNameLike("")`，只忽略部门范围，保留租户隔离；不增加 system 接口或数据库结构。目前旧 RPC 返回目录后由 cost 过滤分页，并非远端数据库分页。真实旧中台 RPC 的租户隔离、账号覆盖和大目录性能仍待验收。
