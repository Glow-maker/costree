# 参考模块清单

状态：初稿

## 1. 目标

固定后续 AI 生成代码时必须仿照的前后端模块，避免生成脱离中台风格的代码。

后续每次生成单个 Vue3 页面、前端 API、Controller、Service、Mapper、DO、Excel VO、SQL 时，都应引用本文件对应参考模块。

## 6. 生成代码时的引用规则

### 6.1 生成 Vue3 页面

必须引用：

- `baseworkhour/index.vue`
- `src/api/finance/baseworkhour/index.ts`
- `hasPermi.ts`
- `download.ts`

要求：

- 页面放在 `src/views/cost/...`
- API 放在 `src/api/cost/...`
- 不引入 React 代码。
- 不重新封装 axios。
- 按钮权限统一用 `v-hasPermi`。

### 6.2 生成导入弹窗

必须引用：

- `BaseWorkImportForm.vue`
- `src/config/axios/service.ts`
- `src/utils/auth.ts`

要求：

- 上传 header 必须带 `Authorization`。
- 租户开启时必须带 `tenant-id`。
- 导入接口使用 `multipart/form-data` 或现有 `el-upload` 方式。

### 6.3 生成后端 CRUD

必须引用：

- `BaseWorkHourController.java`
- `BaseWorkHourServiceImpl.java`
- `BaseWorkHourMapper.java`
- `BaseWorkHourDO.java`

要求：

- 返回值使用 `CommonResult` / `PageResult`。
- Controller 权限用 `@PreAuthorize("@ss.hasPermission('cost:...')")`。
- DO 继承 `BaseDO`。
- Mapper 继承 `BaseMapperX`。
- 分页用 `LambdaQueryWrapperX`，除非确实需要 XML 自定义 SQL。

### 6.4 生成 Excel 导入导出

必须引用：

- `BaseWorkHourController.java`
- `BaseWorkHourImportExcelVO.java`
- `BaseWorkHourServiceImpl#importBaseWorkList`

要求：

- Controller 只负责读写 Excel 和调用 Service。
- 字段校验、重复判断、覆盖逻辑放 Service。
- 返回导入成功/失败明细，不只返回 true/false。

### 6.5 生成消息/预警

必须引用：

- `MessagesController.java`
- `MessagesReceiversController.java`
- `WarnConfigController.java`
- `WarnRecordController.java`
- `WarnCheckJob.java`

要求：

- MVP 先做成本库自己的 10% 超支判断和预警记录。
- “全部推送”先按测试逻辑实现，正式接收人规则标记【需确认】。
- 不直接复制 `MsgApiImpl` 的硬编码示例。

## 7. 当前不建议作为首轮参考

| 对象 | 原因 |
|---|---|
| Figma 生成 React/Vite 代码 | 技术栈不一致，只适合当原型参考 |
| `digital/project` 的权限注释状态 | 权限注解多处被注释，不能作为安全标准 |
| `WarnCheckJob` 全量逻辑 | 文件复杂且依赖现有中心业务，成本库 MVP 只需要 10% 简版预警 |
| `CenterMsgApi#sedMsgs` 实现 | 当前实现存在硬编码作者、接收人、标题、URL，真实推送入口需确认 |

## 8. 后续维护规则

- 每新增一个成本库页面或后端类，都在本文件补充“实际参考了哪个模块”。
- 如果发现更合适的中台参考模块，先更新本文件，再生成代码。
- 如果某个参考模块存在缺陷，必须在“注意”列标明，避免后续复制问题。
