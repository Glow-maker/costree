# 预警与消息推送说明

状态：初稿

## 1. 外网测试假设

| 项 | MVP 假设 |
|---|---|
| 超支阈值 | 10%，即 `thresholdRate = 0.1000` |
| 预警来源 | 第一阶段优先按工作令基础信息计算 |
| 推送对象 | 全部测试用户，记录为 `receiverScope = ALL` |
| 推送通道 | 外网测试先模拟推送，不直接写死中心消息实现 |
| 扫描方式 | 第一阶段优先使用种子数据和手动生成；定时 Job 后置 |

## 2. 目标

先跑通“产生预警记录、查询预警列表、点击推送并记录结果”的闭环。内网接入时，再替换为真实阈值、真实接收人、真实消息通道和真实成本来源。

## 3. 参考中台能力

| 参考能力 | 参考文件 | 可复用点 | MVP 取舍 |
|---|---|---|---|
| 预警定时任务 | `yudao-module-center/.../WarnCheckJob.java` | `@XxlJob`、`@TenantJob`、预警记录新增/更新思路 | 只作为后续定时扫描参考，MVP 不直接复制 |
| 中心预警记录 | `WarnRecordController`、`WarnRecordMapper` 等【需确认具体表结构】 | 中台已有预警记录管理能力 | 成本库先维护自己的 `cost_warning_record` |
| 消息推送 API | `CenterMsgApi#sedMsgs(Long psndocid)` | 说明中心模块已有发送消息入口 | 方法名、参数和业务语义都不适合直接用于成本库，正式接入前必须技术确认 |
| 消息接收人 | `MessagesController`、`MessagesReceiversController`【需确认】 | 可能复用消息表和接收人表 | MVP 先不直接写中心消息表 |

## 4. 预警来源

### 4.1 工作令预警

第一阶段以 `cost_work_order` 为主要来源：

- 目标成本：`product_target_cost`
- 实际/账面成本：`book_cost_amount`
- 项目关联：`project_id`
- 工作令关联：`work_order_id`
- 责任单位：`unit_name`

只有当 `product_target_cost` 和 `book_cost_amount` 都存在，且 `product_target_cost > 0` 时参与计算。

### 4.2 项目汇总预警

项目级预警可由工作令汇总生成，但第一阶段不建议优先实现：

- 汇总目标成本：同一项目下 `product_target_cost` 求和。
- 汇总账面成本：同一项目下 `book_cost_amount` 求和。
- 预警来源：`warning_source = PROJECT`。

是否需要项目级预警、项目级预警是否与工作令预警同时存在【需业务确认】。

## 5. 计算公式

工作令超支率：

```text
overRate = (bookCostAmount - productTargetCost) / productTargetCost
```

超支金额：

```text
overAmount = bookCostAmount - productTargetCost
```

判定规则：

| 条件 | 结果 |
|---|---|
| `productTargetCost <= 0` 或为空 | 不生成预警，或记录为错误数据【需确认】 |
| `bookCostAmount` 为空 | 不生成预警 |
| `overRate >= 0.1000` | 生成或更新 `OVER` 预警 |
| `overRate < 0.1000` | 不生成新预警；已有未关闭预警是否关闭【需确认】 |

MVP 建议只生成 `OVER` 记录，不生成 `NORMAL` 记录；`warning_level` 字段保留 `NORMAL` 是为了后续扩展。

## 6. 预警记录字段写入

目标表：`cost_warning_record`

| 字段 | 写入规则 |
|---|---|
| `project_id` | 来自 `cost_work_order.project_id` |
| `work_order_id` | 工作令预警写工作令 ID，项目汇总预警为空 |
| `warning_source` | 工作令预警为 `WORK_ORDER` |
| `warning_title` | 建议格式：`工作令 {workOrderNo} 成本超支预警` |
| `target_cost_amount` | `product_target_cost` |
| `actual_cost_amount` | `book_cost_amount` |
| `over_amount` | `bookCostAmount - productTargetCost` |
| `over_rate` | 按公式计算，保留 4 位小数【需确认】 |
| `threshold_rate` | 外网测试固定 `0.1000` |
| `warning_level` | 超支写 `OVER` |
| `responsible_unit_name` | `unit_name` |
| `push_status` | 新生成默认 `NOT_PUSHED` |
| `pushed_time` | 推送成功后写当前时间 |
| `receiver_scope` | 外网测试默认 `ALL` |
| `message_id` | 正式接入中心消息后回写【需确认】 |
| `status` | 新生成默认 `OPEN` |

## 7. 记录生命周期

| 状态字段 | 值 | 说明 |
|---|---|---|
| `warning_level` | `OVER` | 当前达到超支阈值 |
| `push_status` | `NOT_PUSHED` | 已生成但未推送 |
| `push_status` | `PUSHED` | 推送动作已成功或外网模拟成功 |
| `push_status` | `FAILED` | 推送动作失败 |
| `status` | `OPEN` | 预警未处理 |
| `status` | `CLOSED` | 预警已关闭 |

已有预警再次扫描时的建议：

- 同一 `tenantId + workOrderId + warningSource + status=OPEN` 已存在时，更新金额、比例、标题和责任单位，不重复新增【需确认】。
- 如果已有预警已 `PUSHED`，再次扫描更新金额时是否重置为 `NOT_PUSHED`【需确认】。
- 如果成本恢复到阈值以下，是否自动 `CLOSED`【需业务确认】。MVP 可以先不自动关闭。

## 8. 预警生成方式

### 8.1 MVP 第一轮

第一轮不优先生成定时任务，先采用以下方式跑通：

1. 使用 `seed-mvp.sql` 预置若干 `cost_warning_record`。
2. 完成 `/cost/warning/page` 查询。
3. 完成 `/cost/warning/push` 模拟推送。

这样可以先验证页面、权限、列表和推送状态变化，不被定时任务和真实消息通道卡住。

### 8.2 MVP 第二轮【可选】

如需要演示从工作令自动产生预警，可增加手动扫描接口【需确认是否开放】：

| 方法 | 路径 | 权限点 | 说明 |
|---|---|---|---|
| POST | `/cost/warning/scan` | `cost:warning:scan` | 按当前工作令数据生成或更新超支预警 |

该接口只建议外网测试或管理员使用，内网正式环境更适合使用定时任务。

### 8.3 后续定时任务

正式定时扫描可以参考 `WarnCheckJob`：

- 使用 `@XxlJob` 注册任务。
- 使用 `@TenantJob` 适配租户。
- 扫描 `cost_work_order` 或真实账面成本来源。
- 批量新增/更新 `cost_warning_record`。

定时任务不是第一阶段首轮生成内容，避免把 MVP 拖入调度平台配置。

## 9. 推送接口

接口：`POST /cost/warning/push`

权限点：`cost:warning:push`

请求字段：

| 字段 | 类型 | 必填 | 说明 |
|---|---|---|---|
| `ids` | `Long[]` | 是 | 预警记录 ID 集合 |
| `receiverScope` | `String` | 否 | 外网测试默认 `ALL` |
| `remark` | `String` | 否 | 推送备注 |

响应字段：

| 字段 | 类型 | 说明 |
|---|---|---|
| `successCount` | `Integer` | 推送成功数量 |
| `failureCount` | `Integer` | 推送失败数量 |
| `failedIds` | `Long[]` | 失败记录 ID |

## 10. MVP 推送实现口径

外网测试先做“模拟推送”：

- 校验预警记录存在。
- 校验记录为 `warning_level = OVER`。
- 将 `push_status` 更新为 `PUSHED`。
- 将 `pushed_time` 更新为当前时间。
- 将 `receiver_scope` 更新为请求值，默认 `ALL`。
- `message_id` 先为空。
- 返回成功/失败统计。

暂不直接调用 `CenterMsgApi#sedMsgs(Long psndocid)`，原因：

- 方法名疑似拼写为 `sedMsgs`，需要确认是否为现行标准接口。
- 参数只有 `psndocid`，不能表达成本库预警标题、内容、接收范围和业务跳转。
- 无法确认其是否写入中心消息表、是否支持多接收人、是否支持租户和业务类型。

正式接入中心消息前，需要技术同事确认应复用哪个 Service/API/table【需技术确认】。

## 11. 与中心消息的后续集成方向

正式集成时建议确认以下方案之一：

| 方案 | 说明 | 风险 |
|---|---|---|
| 复用中心消息 Service | 成本库调用中心模块内部 Service 创建消息和接收人 | 跨模块依赖方式需确认 |
| 复用中心消息 API | 成本库通过 Feign/RPC 调中心消息 API | 需要标准 API 支持标题、内容、接收人、跳转链接 |
| 仅写成本库预警表 | 成本库页面展示预警，不进入中心消息 | 与“消息推送”业务诉求可能不一致 |

建议内网确认后，把 `message_id` 回写到 `cost_warning_record.message_id`，便于追踪推送结果。

## 12. 推送幂等和重复推送

MVP 可先允许重复点击推送，但需要明确表现：

| 场景 | 建议处理 |
|---|---|
| `NOT_PUSHED` 记录推送 | 更新为 `PUSHED` |
| `PUSHED` 记录再次推送 | 允许重复，刷新 `pushed_time`【需确认】 |
| `FAILED` 记录再次推送 | 允许重试 |
| `CLOSED` 记录推送 | 建议拦截【需确认】 |

如果业务不允许重复通知，需要在 Service 层拦截 `push_status = PUSHED` 的记录。

## 13. 权限和数据权限

- 查询权限：`cost:warning:query`。
- 推送权限：`cost:warning:push`。
- 如果增加手动扫描接口，权限为 `cost:warning:scan`。
- 预警查询需遵守成本项目的数据权限规则【需确认】。
- 管理层是否能看全部预警、项目办是否只能看本领域/本项目、研制单位是否只能看本单位【需业务确认】。

## 14. 后续生成代码边界

- 第一轮只生成 `/page` 和 `/push`。
- 不生成正式中心消息写入逻辑。
- 不生成定时任务，除非业务要求演示自动扫描。
- 不把预警阈值做成复杂配置中心，先固定 `0.1000`；正式阈值配置后续再扩展【需确认】。
- 不把驾驶舱统计和预警列表混在一个接口里。

## 15. 待确认

- 预警来源是否只按工作令，还是项目汇总和工作令都要预警。
- 真实账面成本字段来自成本库填报，还是来自财务/ERP/数据中台其它表。
- 超支阈值是否全局固定 10%，还是按领域、型号、阶段、单位配置。
- 成本恢复到阈值以下时，预警是否自动关闭。
- 推送接收人是全部用户、项目负责人、项目办、研制单位，还是角色/组织组合。
- 中心消息最终复用哪个 API、Service 或数据表。
- 重复推送是否允许。
