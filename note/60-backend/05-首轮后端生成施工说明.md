# 首轮后端生成施工说明

状态：初稿

## 1. 目标

把成本库后端首轮代码生成拆成可控小步，后续每次只让 AI 生成一个明确批次，并且每个批次都有输入文档、文件边界、禁止事项和验收标准。

本文件只用于指导后续代码生成，不在当前阶段生成 Java 代码。

## 2. 当前假设

| 项 | 假设 |
|---|---|
| 后端仓库 | `<backend-root>` |
| 首选模块形态 | 新增 `yudao-module-cost` |
| 模块结构 | 仿照 `yudao-module-finance`，包含 `yudao-module-cost-api` 和 `yudao-module-cost-biz` |
| Java 版本 | JDK 8，不能使用 Java 17 语法 |
| 数据库 | 外网测试使用 `costree_mvp`，连接信息只看 `80-deployment/00-环境账号与敏感信息.md` |
| 首轮业务范围 | B1 模块骨架、B2 型号树和成本项目只读链路 |

【需技术确认】是否允许新增 `yudao-module-cost`。如果不允许，首轮提示词必须改为“在既有模块下新增 `cost` 子包”，不能同时走两种方案。

## 3. 每次生成代码前必须读取

| 文档 | 用途 |
|---|---|
| `10-research/03-参考模块清单.md` | 固定仿照的中台代码风格 |
| `30-data/schema-mvp.sql` | 固定表名、字段名、字段类型 |
| `40-api/01-接口清单-MVP.md` | 固定接口路径和权限点 |
| `40-api/02-接口字段契约.md` | 固定请求和响应字段 |
| `60-backend/01-yudao-module-cost后端设计.md` | 固定模块、包路径、权限原则 |
| `60-backend/02-Controller-Service-Mapper生成清单.md` | 固定生成批次和文件清单 |

每次让 AI 生成代码时，要在提示词里明确“以上文件已经是口径来源，冲突时先停下来说明冲突，不要自行发明字段”。

## 4. 首轮批次

| 批次 | 目标 | 是否首轮执行 | 说明 |
|---|---|---|---|
| B0 | 开工前检查 | 是 | 不改代码，只检查 Maven、模块、参考文件 |
| B1 | 模块骨架 | 是 | 建立 `yudao-module-cost`、`api`、`biz` 和基础包 |
| B2-1 | 型号树只读链路 | 是 | 实现 `/cost/model-node/tree` |

## 5. B0 开工前检查

### 5.1 目标

确认后端仓库当前状态，避免在错误目录、错误模块或脏变更上直接生成代码。

### 5.2 只读检查项

| 检查项 | 说明 |
|---|---|
| `pom.xml` 根模块 | 是否已有 `yudao-module-cost` |
| `yudao-module-finance` | 确认可作为模块骨架参考 |
| `FinanceServerApplication.java` | 确认启动类、包路径和注解风格 |
| Git 状态 | 如果仓库是 Git 仓库，先看是否已有他人改动 |
| 数据库脚本 | 确认 `schema-mvp.sql` 已包含 B2 需要的 `cost_model_node`、`cost_project` |

### 5.3 建议提示词

```text
请只做只读分析，不要修改代码。

后端仓库：<backend-root>

请检查：

输出要求：
- 只输出检查结论和文件清单；
- 不要写 Java 代码；
- 不确定项标记【需确认】。
```

### 5.4 验收标准

- 明确是否可以新增 `yudao-module-cost`。
- 明确 B1 需要修改哪些 `pom.xml`。
- 明确是否存在已有 `yudao-module-cost` 或命名冲突。
- 没有发生文件改动。

## 7. B2-1 型号树只读链路

### 7.1 目标

实现领域-系列-型号三级树查询接口：

```text
GET /cost/model-node/tree
```

权限点：

```text
cost:project:query
```

### 7.2 文件范围

| 文件 | 说明 |
|---|---|
| `CostModelNodeDO.java` | 对应 `cost_model_node` |
| `CostModelNodeMapper.java` | 查询节点列表 |
| `CostModelNodeService.java` | Service 接口 |
| `CostModelNodeServiceImpl.java` | 查询并组装树 |
| `CostModelNodeListReqVO.java` | 查询参数 |
| `CostModelNodeRespVO.java` | 响应字段，包含 `children` |
| `CostModelNodeController.java` | 暴露 `/cost/model-node/tree` |

不生成：

- 新增节点接口。
- 编辑节点接口。
- 删除节点接口。
- Excel 导入导出。

### 7.3 实现规则

- 默认过滤 `deleted = 0`。
- 默认只查 `status = ENABLE`【需确认】。

- 返回树形结构，字段以 `40-api/02-接口字段契约.md` 为准。
- `parent_id = 0` 视为根节点。
- 排序使用 `sort` 升序，再按 `id` 升序【需确认】。

## 8. B2-2 成本项目只读链路

### 8.1 目标

实现成本项目/主业项目锚定信息查询：

```text
GET /cost/project/page
GET /cost/project/get?id=
```

权限点：

```text
cost:project:query
```

### 8.2 文件范围

| 文件 | 说明 |
|---|---|
| `CostProjectDO.java` | 对应 `cost_project` |
| `CostProjectMapper.java` | 分页和详情查询 |
| `CostProjectService.java` | Service 接口 |
| `CostProjectServiceImpl.java` | 查询实现 |
| `CostProjectPageReqVO.java` | 分页查询参数 |
| `CostProjectRespVO.java` | 响应字段 |
| `CostProjectController.java` | 暴露 `/cost/project/page`、`/cost/project/get` |

可暂不生成：

- `CostProjectUpdateStatusReqVO.java`
- `/cost/project/update-status`

如果业务需要在首轮演示草稿/提交状态，可把状态接口作为 B2-3 单独生成。

### 8.3 实现规则

- 分页响应使用 `CommonResult<PageResult<CostProjectRespVO>>`。
- 详情响应使用 `CommonResult<CostProjectRespVO>`。
- Mapper 使用 `BaseMapperX` + `LambdaQueryWrapperX`。
- 支持接口契约中的筛选字段：`projectCode`、`projectName`、`domainCode`、`categoryCode`、`modelCode`、`unitName`、`projectOfficeStatus`、`unitFillStatus`、`auditStatus`、`warningStatus`。
- `projectName`、`unitName` 建议模糊查询；编码字段建议精确查询【需确认】。
- 不允许前端通过该接口修改主业项目锚定信息。

## 9. B2-3 成本项目状态接口【可选】

### 9.1 触发条件

只有在以下条件满足时才做：

- 业务确认 MVP 首轮必须展示“保存草稿/提交”。
- 技术确认状态只改 `cost_project.audit_status`，还是要联动项目基本情况/工作令。

### 9.2 建议暂缓原因

状态流转看似简单，但会影响项目办和研制单位的权限边界。当前文档中仍有以下不确定项：

- 项目级统一提交，还是项目基本情况/工作令分别提交【需确认】。
- 提交后是否禁止编辑【需确认】。
- 退回、审批是否进入 BPM【需确认】。

因此建议 B2-3 放在 B3 前单独确认。

## 10. 通用禁止事项

每次生成代码时都要明确禁止：

- 不生成 React 代码。
- 不改前端 `costree-frontend`，除非任务明确要求。
- 不改 `schema-mvp.sql` 和 `seed-mvp.sql`，除非任务明确要求。
- 不把外网数据库账号密码写进 Java 配置。
- 不生成 `table2`、`table3` 命名。
- 不复制参考模块中的调试输出。
- 不绕开 `@PreAuthorize`。
- 不一次生成 B3、B4、B5。
- 不引入未确认的消息推送、BPM、定时任务。

## 11. 通用验收清单

| 检查项 | 标准 |

## 12. 推荐执行顺序

1. 执行 B0，只读检查。
2. 用户确认是否允许新增 `yudao-module-cost`。
3. 执行 B1，建立模块骨架。
4. 编译通过后，执行 B2-1。
5. 编译和接口联调通过后，执行 B2-2。
6. 再决定是否做 B2-3。
7. B2 全部稳定后，再进入 B3 项目基本情况 CRUD。
