# 导入导出实现说明

状态：初稿

## 1. 目标

定义成本库 MVP 的 Excel 模板下载、导入校验、导入结果记录、错误明细返回和导出规则。后续生成后端 Controller、Service、ExcelVO、导入批次表写入逻辑时，以本文件为实现口径。

## 2. 先做范围

- 先支持两个业务模板：项目基本情况、工作令基础信息。
- 先支持外网 MySQL 测试数据，真实主数据、真实组织和真实字典后续替换。
- 先复用中台已有 `ExcelUtils`、EasyExcel 注解、`MultipartFile` 上传方式。
- 先把导入结果写入 `cost_import_batch` 和 `cost_import_error`。
- 失败信息先通过接口返回错误明细；是否生成错误 Excel 文件【需确认】。

## 4. 接口范围

| 业务 | 方法 | 路径 | 权限点 | 说明 |
|---|---|---|---|---|
| 项目基本情况 | GET | `/cost/project-basic/get-import-template` | `cost:project-basic:import` | 下载项目基本情况模板 |
| 项目基本情况 | POST | `/cost/project-basic/import` | `cost:project-basic:import` | 导入项目基本情况 |
| 项目基本情况 | GET | `/cost/project-basic/export-excel` | `cost:project-basic:export` | 导出当前筛选结果 |
| 工作令基础信息 | GET | `/cost/work-order/get-import-template` | `cost:work-order:import` | 下载工作令基础信息模板 |
| 工作令基础信息 | POST | `/cost/work-order/import` | `cost:work-order:import` | 导入工作令基础信息 |
| 工作令基础信息 | GET | `/cost/work-order/export-excel` | `cost:work-order:export` | 导出当前筛选结果 |

导入请求参数：

| 参数 | 类型 | 必填 | 说明 |
|---|---|---|---|
| `file` | `MultipartFile` | 是 | Excel 文件 |
| `updateSupport` | `Boolean` | 否 | 是否覆盖已有数据，默认 `false` |

导入响应统一使用 `CostImportResultRespVO`，字段见 `40-api/02-接口字段契约.md`。

| 7 | 阶段集合 | `stageCodes` | 是【需确认】 | 先用逗号分隔，如 `STAGE_A,STAGE_B` |
| 8 | 最高阶段 | `maxStageCode` | 否 | 可由后端按阶段排序计算【需确认】 |

| 14 | 备注 | `remark` | 否 | 文本 |

导入落表：

- 目标表：`cost_work_order`。

- 根据 `unitName` 可先写入文本；内网是否映射 `unit_id`【需确认】。
- `status` 默认 `DRAFT`。
- `import_batch_id` 写入本次 `cost_import_batch.id`。
- `book_cost_amount` 第一阶段仅用于预警演示，真实账面成本来源【需确认】。

## 7. 校验规则

通用校验：

| 规则 | 处理方式 |
|---|---|
| 文件为空 | 返回导入失败，错误码参考 `COST_IMPORT_FILE_EMPTY` |
| Excel 解析失败 | 返回导入失败，提示模板格式错误 |
| `projectCode` 不存在 | 当前行失败，写入 `cost_import_error` |
| 金额字段小于 0 | 当前行失败 |
| 文本字段超长 | 当前行失败，长度按数据库字段限制 |
| 阶段值不在枚举范围 | 当前行失败【需确认字典来源】 |
| 同一文件内重复业务键 | 后一行失败，提示与前序行重复【需确认】 |

项目基本情况校验：

- `cycleStart`、`cycleEnd` 格式必须为 `YYYY-MM`。
- 当 `cycleStart` 和 `cycleEnd` 均有值时，`cycleEnd` 不能早于 `cycleStart`。
- `targetCostAmount`、`targetPrice`、`competitorPrice1`、`competitorPrice2`、`contractAmount`、`approvedAmount` 不能小于 0。
- 是否允许同一个项目存在多条项目基本情况记录，需要按 `projectId + subsystemName + stageCode` 还是其它业务键判断重复【需确认】。

工作令基础信息校验：

- `workOrderNo` 租户内唯一。
- `productTargetCost`、`bookCostAmount`、`approvedAmount` 不能小于 0。
- `quantity` 必须大于 0。
- `verticalDivision` 允许 `是/否`、`Y/N`、`true/false` 的映射范围【需确认】。
- `maxStageCode` 如果为空，可按 `stageCodes` 计算；阶段排序规则【需确认】。

## 8. `updateSupport` 规则

### 8.1 项目基本情况

重复业务键暂定为 `tenantId + projectId + subsystemName + stageCode`【需确认】。

| 场景 | `updateSupport=false` | `updateSupport=true` |
|---|---|---|
| 未找到重复记录 | 新增 | 新增 |
| 找到重复记录 | 当前行失败 | 覆盖更新原记录 |

覆盖更新时：

- 保留原记录 `id`、`creator`、`createTime`。
- 更新导入字段、`updater`、`updateTime`、`importBatchId`。
- 不自动把 `status` 从 `SUBMITTED` 改回 `DRAFT`【需确认】。

### 8.2 工作令基础信息

重复业务键暂定为 `tenantId + workOrderNo`。

| 场景 | `updateSupport=false` | `updateSupport=true` |
|---|---|---|
| 未找到 `workOrderNo` | 新增 | 新增 |
| 找到 `workOrderNo` | 当前行失败 | 覆盖更新原记录 |

覆盖更新时：

- 不允许把工作令移动到另一个 `projectId`【需确认】。如果 Excel 中 `projectCode` 与原记录不一致，建议当前行失败。
- 保留原记录 `id`、`creator`、`createTime`。
- 更新导入字段、`updater`、`updateTime`、`importBatchId`。

## 9. 导入批次和错误明细

每次导入都写入 `cost_import_batch`：

| 字段 | 写入规则 |
|---|---|
| `import_type` | `PROJECT_BASIC` 或 `WORK_ORDER` |
| `file_name` | 原始上传文件名 |
| `file_url` | 外网测试可为空；如接入文件服务再写真实地址【需确认】 |
| `total_count` | 解析后的数据行数 |
| `success_count` | 成功新增或更新行数 |
| `failure_count` | 失败行数 |
| `update_support` | 请求参数 |
| `status` | 全成功 `SUCCESS`，部分成功 `PART_SUCCESS`，全失败 `FAILED` |
| `error_file_url` | 第一阶段可为空；是否生成错误文件【需确认】 |

失败行写入 `cost_import_error`：

| 字段 | 写入规则 |
|---|---|
| `batch_id` | 本次导入批次编号 |
| `row_num` | Excel 原始行号，表头下一行从 2 开始 |
| `field_name` | 失败字段，整行错误可为空 |
| `error_message` | 面向用户可读的失败原因 |
| `raw_data` | 原始行数据 JSON，注意不要写入敏感信息 |

## 10. 返回结果

导入接口返回 `CommonResult<CostImportResultRespVO>`：

| 字段 | 说明 |
|---|---|
| `batchId` | 导入批次编号 |
| `importType` | `PROJECT_BASIC` / `WORK_ORDER` |
| `fileName` | 原始文件名 |
| `totalCount` | 总行数 |
| `successCount` | 成功行数 |
| `failureCount` | 失败行数 |
| `status` | `SUCCESS` / `PART_SUCCESS` / `FAILED` |
| `errors` | 错误明细，建议最多返回前 100 条【需确认】 |

接口是否在存在失败行时返回业务失败码，还是始终返回成功并由 `status` 表达导入结果【需确认】。建议 MVP 采用“接口成功 + 业务状态”的方式，便于前端展示部分成功。

## 11. 导出规则

- 导出接口复用分页查询参数，但导出时不分页，导出当前筛选条件下的全部数据。
- 导出必须受按钮权限控制：`cost:project-basic:export`、`cost:work-order:export`。
- 导出也必须受数据权限控制【需确认中台数据权限接入方式】。
- 文件名建议：
  - `项目基本情况.xls`
  - `工作令基础信息.xls`
- Sheet 名建议：
  - `项目基本情况`
  - `工作令基础信息`
- 导出字段优先与列表字段一致；是否包含审计字段【需确认】。

## 12. 后续生成代码边界

- 第一轮生成项目基本情况 CRUD 后，再补项目基本情况导入导出。
- 第二轮生成工作令基础信息 CRUD 后，再补工作令导入导出。
- 不要在导入导出阶段顺手生成驾驶舱、BPM、正式消息推送。
- 不要把模板字段命名为 `Table 2`、`Table 3`。
- 不要在成本库代码里硬编码外网数据库连接信息。

## 13. 待确认

- 项目基本情况重复键到底采用什么字段。

- 导入存在部分失败时，接口 HTTP/业务响应码如何约定。
- 阶段、获取方式、纵向分工等枚举最终来自中台字典还是成本库自建字典。
- 导出字段是否包含审计字段、提交状态、导入批次编号。
