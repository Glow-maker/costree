# 研制单位只按单位授权及空主键修正

2026-09-09 用户现场截图显示 `CostUserProjectScopeMapper.insert` 批量 INSERT 显式传入 `id=NULL`，触发非空约束。不是 warning 表缺失；现有 DEFAULT 即使存在也不会替代显式 NULL。现场到底是哪项配置或序列生成器初始化导致 ID 未生成，尚未直接读取运行配置，不能认定唯一配置根因。

用户同时重申研制单位无需选择型号/项目。此次工作区修正：

- 前端 `src/views/cost/accessScope/index.vue`：项目选择器只对项目办显示，研制单位仅要求管理单位，提交 projectCodes 为空。
- 后端范围服务：研制单位只保存管理单位，忽略请求中旧 projectCodes 并清除旧项目范围；通过当前租户工作令和单位成本记录的 unit_name 与有效管理单位/核算单位名匹配，动态取得关联项目。业务数据仍按项目与单位限制，不授予全量权限；无关联项目、无单位或失效单位均不能通过范围鉴权。
- 三类范围 DO（项目、单位、领域）：显式使用 ASSIGN_ID，由应用插入处理生成主键，不依赖现场全局 INPUT 或序列生成器。保留已有 ID、数据库序列和约束，无需 DDL 变更。
- API 字段契约和联调用例已同步更新，注明为尚未发布的工作区行为。管理员原页面与项目办/科研部规则保留。
