# 业务方建表参考对照与调整建议

状态：初稿

更新时间：2026-05-22

## 结论

业务方提供的建表参考需要吸收，但不建议直接替换我们已有的 MVP 表。

原因是两边定位不同：

| 类型 | 定位 | 代表表 |
|---|---|---|
| 业务方参考表 | 源系统/治理数据落库，强调保留原始字段、增量同步、凭证明细追溯 | 主业项目树、工作令关联主业项目字典、项目工作令账面成本明细 |
| 我们现有 MVP 表 | 成本库页面展示、填报、导入、权限和预警使用的业务表 | `cost_project`、`cost_work_order`、`cost_unit_cost_detail` |

因此本轮采取“新增源数据表 + 保留现有业务表”的方式：

- 新增 `cost_source_project_tree`：保留业务方“主业项目树”源数据。
- 新增 `cost_work_order_project_ref`：保留“工作令关联主业项目字典”。
- 新增 `cost_work_order_ledger_detail`：保留“项目工作令账面成本明细数据”。
- 现有 `cost_model_node`、`cost_project`、`cost_work_order`、`cost_unit_cost_detail` 继续支撑前台展示和填报。

## 表一：主业项目树

业务方字段：

| 业务字段 | 当前是否覆盖 | 调整建议 |
|---|---|---|
| 项目主键ID `xmnm` | 部分覆盖，当前没有保留源主键 | 新增 `cost_source_project_tree.source_project_id` |
| 主业项目编号 | 已覆盖 | `cost_project.project_code` 和源表 `project_code` 都保留 |
| 主业项目名称 | 已覆盖 | `cost_project.project_name` 和源表 `project_name` 都保留 |
| 主业项目所属类别 | 部分覆盖 | 现有 `category_name` 可展示，源表保留 `project_category` |
| 所属领域 | 已覆盖 | `domain_code` / `domain_name` |
| 父路径/上级节点 ID | 当前业务表不完整 | 源表保留 `parent_source_id`、`parent_path` |
| 级数 JS | 当前未覆盖 | 源表保留 `level_no` |
| 自定义1-10 | 当前未覆盖 | 源表保留 `custom_01` 至 `custom_10` |
| 最后修改时间 | 当前只保留中台更新时间 | 源表保留 `source_lastmodify`，用于增量同步 |

建议口径：

- `cost_source_project_tree` 作为源数据事实表，用于接院 cloud / 治理数据。
- `cost_model_node` 继续作为成本库前端树形展示表。
- `cost_project` 继续作为成本库项目锚定表。
- 同步任务后续按 `source_project_id` 和 `source_lastmodify` 增量更新源表，再转换或匹配到业务表。

## 表二：工作令关联主业项目字典

业务方字段：

| 业务字段 | 当前是否覆盖 | 调整建议 |
|---|---|---|
| 工作令ID | 当前未覆盖源 ID | 新增 `cost_work_order_project_ref.source_work_order_id` |
| 核算单位编号/名称 | 部分覆盖 | 源表保留 `accounting_unit_code`、`accounting_unit_name` |
| 年度 | 当前未覆盖 | 源表保留 `fiscal_year` |
| 工作令编号/名称 | 已覆盖 | 业务表和源表都保留 |
| 是否停用 | 当前未覆盖 | 源表保留 `disabled` |
| 关联主业项目编号/名称/ID | 部分覆盖 | 源表保留 `linked_project_code`、`linked_project_name`、`linked_source_project_id` |
| 自定义1-10 | 当前未覆盖 | 源表保留 `custom_01` 至 `custom_10` |

建议口径：

- `cost_work_order_project_ref` 保存“当前状态”的工作令到主业项目映射。
- `cost_work_order` 仍是成本库的工作令基础信息填报表。
- 如果源字典映射变更，历史账面成本明细是否按原映射追溯或按新映射重算，需要业务确认【需确认】。

## 表三：项目工作令账面成本明细数据

业务方字段包含凭证、科目、项目、工作令、金额、摘要、最后修改时间等明细。当前 `cost_unit_cost_detail` 是项目/阶段/单位聚合后的成本结构表，不适合承载凭证明细。

本轮新增 `cost_work_order_ledger_detail`。

| 业务字段 | 新字段 |
|---|---|
| `ysnm` 内码 | `source_detail_id` |
| `kjnd` 会计年度 | `fiscal_year` |
| `kjqj` 会计期间 | `accounting_period` |
| `pzrq` 凭证日期 | `voucher_date` |
| `pzbh` 凭证编号 | `voucher_no` |
| `dwid` / `dwbh` / `dwmc` | `accounting_unit_id` / `accounting_unit_code` / `accounting_unit_name` |
| `gldw` 管理单位 | `manage_unit_name` |
| `kmid` / `kmbh` / `kmmc` | `subject_id` / `subject_code` / `subject_name` |
| `xmbh` / `xmnm` / `xmmc` | `project_code` / `source_project_id` / `project_name` |
| `gzlnm` / `gzllb` / `gzlmc` | `source_work_order_id` / `work_order_no` / `work_order_name` |
| `jzfx` 记账方向 | `debit_credit` |
| `je` 金额 | `amount`，源系统单位【需确认，当前暂按元】 |
| `yt` 辅助摘要 | `summary_text` |
| `lastmodify` 最后修改时间 | `source_lastmodify` |

额外增加：

- `amount_wan`：折算万元，便于前端展示和聚合【需确认换算口径】。
- `resolved_stage_code`：按工作令最高阶段归集后的阶段。
- `project_id`、`work_order_id`：匹配到成本库业务表后的主键。

## 查询表格 1：成本树型号基础信息

业务方给的是查询页面字段，不一定需要单独建物理表。

建议第一阶段通过接口实时组合：

| 展示字段 | 建议来源 |
|---|---|
| 所属领域 | `cost_project` / `cost_source_project_tree` |
| 主业项目编号/名称 | `cost_project` |
| 主业项目所属类别 | `cost_project.category_name` 或 `cost_source_project_tree.project_category` |
| 核算单位编号/名称 | `cost_work_order_project_ref` / `cost_unit_dict` |
| 单位属性 | `cost_unit_dict.inside_institute` 计算院内/院外/院本级支出【需确认院本级判断口径】 |
| 到款金额 | 当前可用 `cost_unit_cost_detail.income_amount`，正式来源【需确认】 |
| 预分预控金额 | 可能对应目标成本或预控额度，正式字段含义【需确认】 |
| 备注 | 源表或业务表备注 |

暂不新增查询结果物理表。后续如果性能不足，再考虑建视图或汇总表。

## 对当前页面逻辑的影响

短期：

- 成本树详情页仍可继续使用现有 `cost_project`、`cost_work_order`、`cost_unit_cost_detail`。
- 新增源表暂不影响现有前端和后端接口。
- 外网测试库可先用 `seed-mvp.sql` 里的源数据样例验证字段口径。

中期：

- 账面成本应逐步改为从 `cost_work_order_ledger_detail` 按工作令聚合，而不是只依赖 `cost_work_order.book_cost_amount`。
- 工作令到项目的归属应优先参考 `cost_work_order_project_ref`。
- 主业项目树的正式来源应以 `cost_source_project_tree` 的源 ID 和最后修改时间为准。

## 需业务和技术确认

- 【需确认】源系统金额 `je` 的单位是元、万元还是其他口径。
- 【需确认】贷方/冲销金额在账面成本聚合时是否直接按负数计入。
- 【需确认】工作令映射发生变化时，历史凭证明细按发生时映射追溯，还是按当前映射重算。
- 【需确认】“预分预控金额”是否等同于目标成本，还是需要独立字段。
- 【需确认】“院本级支出”判断规则，是核算单位为院部，还是管理单位为院部，或来自独立标识。
- 【需确认】源项目树的三层级和我们现有“领域-系列-型号”是否完全等价；如果不等价，需要保留转换规则。
