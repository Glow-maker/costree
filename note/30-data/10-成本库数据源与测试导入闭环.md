# 10-成本库数据源与测试导入闭环

状态：可执行测试方案  
更新时间：2026-07-21  
适用对象：项目负责人、数据治理人员、内网 DBA、后端开发、演示人员

## 1. 一句话说明

成本库不直接拿外部原表给页面使用，而是先把外部数据整理后写入成本库业务表：

```text
外部系统原表 -> 校验和转换 -> 成本库业务表 -> 首页、目录、成本树和单位穿透
```

这样既保留源数据，又能保证页面字段、金额单位和关联关系稳定。

## 2. 需要哪些外部数据

| 数据来源 | 提供什么 | 成本库落表 | 页面作用 |
|---|---|---|---|
| 单位字典 | 核算单位、管理单位简称、管理单位分类、院内外标识 | `cost_unit_dict` | 单位分组、电子所等管理单位汇总 |
| 主业项目树 `ads_lc_lshsxm2022` | 项目节点、项目编码、名称、父节点、级数 | `cost_model_node`、`cost_project` | 目录树、项目卡片、成本树根节点 |
| 工作令映射 `dwd_bd_bfcustomitem_gzl` | 工作令编号、名称、核算单位、关联项目 | `cost_work_order` | 项目下的工作令和单位穿透 |
| 预分预控治理结果 | 项目 + 单位的合同、到款、目标、审定金额 | `cost_unit_cost_detail` | 首页和成本树金额、单位目标 |
| 项目办补充数据 | 用户、获取方式、批次、周期、当前阶段、分系统 | `cost_project_basic` | 采集页、目录卡片、项目详情 |
| 研制单位补充数据 | 工作令阶段、分系统、产品简称、数量、纵向分工 | `cost_work_order` | 工作令详情和阶段筛选 |
| 账面明细 `dws_bu_pz_pzmx_gzl` | 凭证、年度、单位、项目、工作令、科目、借贷、金额 | `cost_work_order_ledger_detail` | 账面成本、八项组成、年度明细 |

中台租户、组织、账号和权限继续使用现有中台数据，不在成本库重复建表。

## 3. 当前金额以谁为准

| 金额 | 权威来源 | 单位和规则 |
|---|---|---|
| 合同金额 | 预分预控项目单位金额 | 万元，按项目 + 核算单位累计值 |
| 到款金额 | 预分预控项目单位金额 | 万元，按项目 + 核算单位累计值 |
| 目标成本 | 预分预控项目单位金额 | 万元，单位预警的分母 |
| 审定金额 | 预分预控项目单位金额 | 万元 |
| 账面成本 | 工作令账面明细 | 源 `je` 为元，标准表同时保存元和万元；只统计借方 |
| 八项组成 | 工作令账面明细的 `501101-501108` | 只汇总借方，缺少的科目显示为 0 |

`cost_work_order.book_cost_amount` 是“项目 + 实际核算单位 + 工作令编号 + 年度”的借方账面快照，可以从明细重建。项目基本信息和工作令里的历史合同、目标字段只保留兼容，不再是页面金额权威来源。

## 4. 测试源表怎么模拟

PostgreSQL 测试库增加独立 schema：`cost_demo_source`。它只用于模拟外部系统，不属于生产业务表。

| 测试表 | 模拟对象 |
|---|---|
| `unit_dict` | 内网单位字典 |
| `ads_lc_lshsxm2022` | 内网主业项目树 |
| `dwd_bd_bfcustomitem_gzl` | 工作令关联主业项目字典 |
| `precontrol_project_unit_amount` | 预分预控治理结果 |
| `project_office_fill` | 项目办非财务补充字段 |
| `work_order_fill` | 研制单位工作令补充字段 |
| `dws_bu_pz_pzmx_gzl` | 工作令账面凭证明细 |
| `demo_config` | 测试租户、批次和同步标记 |

三个已知内网原表保留原字段名和字符串类型；预分预控真实表名尚未确定，因此测试表先采用清晰的标准字段。正式对接时可以建立视图，把真实字段改名成测试表字段，后续同步 SQL 不需要重写。

## 5. 如何执行

脚本目录：

```text
<backend-root>/sql/postgresql/costree-demo-source/
```

执行顺序：

```text
00-create-source-schema.sql  创建模拟源表
01-seed-two-projects.sql     准备两个项目的源数据
02-sync-to-cost.sql          校验并同步到成本库
03-verify.sql                自动对账并输出结果
```

为了验证幂等性，再执行一次 `02` 和 `03`。第二次执行后记录数和金额不能增加。需要清理时执行 `99-cleanup.sql`，它只处理两个专用演示项目。

如果 SQL 客户端显示 `current transaction is aborted`，说明前面已有语句失败。先查看第一条错误，执行 `ROLLBACK;`，再从当前文件开头重新执行。

## 6. 两个演示项目

### 6.1 单位层级项目

项目编码：`ZY-2026-DEMO-UNIT-001`

- 12 个院内核算单位，按管理单位简称汇总为 10 张院内卡片。
- 覆盖总体所、总装所、专业所、基础所、院外单位五类。
- 电子所包含 3 个实际核算单位，验证“卡片汇总、工作令不错误合并”。
- 院内目标 10,720 万元，借方账面 10,800 万元。
- 800所和 803所为黄色，149厂为红色，其余院内管理单位正常。
- 八项借方组成合计 10,800 万元。

### 6.2 跨年度项目

项目编码：`ZY-2026-DEMO-YEAR-002`

- 同一单位、同一工作令编号包含 2023-2026 四条年度工作令。
- 年度账面分别为 200、250、200、350 万元，合并卡片为 1,000 万元。
- 包含 8 条借方科目和 2 条贷方冲销，贷方保留但不参加账面与组成统计。

两个项目合计：14 条项目单位金额、16 条年度工作令、22 条账面明细，借方账面 11,800 万元。

## 7. 演示页面


## 8. 正式接入时替换什么

测试表只是外部源的替身。正式内网接入时：

1. 用真实单位字典替换 `unit_dict`。
2. 用真实主业项目树替换 `ads_lc_lshsxm2022`。
3. 用真实工作令映射替换 `dwd_bd_bfcustomitem_gzl`。
4. 用预分预控治理表或视图替换 `precontrol_project_unit_amount`。
5. 用真实账面凭证明细替换 `dws_bu_pz_pzmx_gzl`。
6. 保留项目办和研制单位补充字段入口。
7. 先在临时表校验，再 UPSERT 到业务表，最后执行同样的对账 SQL。

正式工作流不能无条件 `INSERT`。必须使用稳定源 ID 和现有三个业务唯一键，保证重复同步不会重复记账。
