# 外部源全量快照中间表幂等同步

## 一句话说明

外部源每次把完整数据放入独立中间表；成本库按稳定业务键更新已有行、插入新行。每批只清空中间表，不清空成本库业务表。

```text
主业项目树 / 单位 / 预分预控 / 工作令 / 凭证明细
                         ↓ 全量快照
                 cost_sync_stage 中间表
                         ↓ 检查
                  UPDATE 已有 + INSERT 新增
                         ↓
                  cost_* 成本库业务表
```

可执行脚本位于：

`deploy/cost-server-offline-template/database/postgresql92/03-data-integration/snapshot-upsert/`

## 中间表和目标表

| 中间表 | 外部来源 | 目标业务表 |
|---|---|---|
| `stg_unit_dict` | 权威单位字典 | `cost_unit_dict` |
| `stg_model_node` | 主业项目树解析节点 | `cost_model_node` |
| `stg_project` | 主业项目树叶子项目 | `cost_project` |
| `stg_unit_amount` | 预分预控项目单位金额 | `cost_unit_cost_detail` |
| `stg_work_order` | 工作令关联项目字典 | `cost_work_order` |
| `stg_ledger_detail` | 工作令凭证明细 | `cost_work_order_ledger_detail` |

## 业务键

| 目标表 | 更新和新增使用的键 |
|---|---|
| 单位字典 | 租户 + 实际核算单位编码 |
| 型号树 | 租户 + 节点编码 |
| 项目 | 租户 + 主业项目编号 |
| 单位金额 | 租户 + 项目编号 + 实际核算单位名称 |
| 工作令 | 租户 + 项目编号 + 实际核算单位名称 + 工作令编号 |
| 账面明细 | 租户 + 源明细 ID |

实际核算单位是存储和关联口径，电子所、800所等管理单位简称只用于页面汇总。单位名称或编码不一致会造成单位卡片、工作令和预分预控金额无法闭环。

## 字段保护

外部同步可以覆盖：

- 单位字典映射和启停状态。
- 项目名称和目录树归属。
- 项目单位合同、到款。
- 工作令源主键、编号、名称、实际单位和停用状态。
- 账面明细全部源字段。
- 由借方明细重算的工作令账面快照。

外部同步不能覆盖：

- 项目办填写的单位目标和审定。
- 研制单位填写的工作令合同、到款、目标、审定、阶段、分系统、产品、配套数和纵向分工。
- `cost_project_basic`、授权关系、预警处理记录。

## 删除规则

源快照中缺少旧记录时不自动删除，因为缺失也可能是抽取失败。脚本只生成差异清单。

确需停用或删除时，源系统下一批仍要保留该行，并明确传 `disabled=1` 或 `source_deleted=1`。这样不会因一次不完整快照误删已经填报的数据。

## 每批步骤

1. `02` 只清空中间表。
2. 源数据全量装入六张中间表。
3. `04` 检查空键、重复键、引用和金额格式。
4. `05` 按业务键 UPDATE + INSERT。
5. `06` 按全部年度借方明细重算工作令账面。
6. `07` 对账验收。
7. `08` 输出源缺失差异，人工处理。

以上步骤按文件分阶段提交，不是一个跨文件原子事务：`05` 提交后状态为 `BUSINESS_SYNCED`，`06` 提交后为 `RECALCULATED`，只有 `07` 验收通过后才标记 `SUCCESS`。失败时只回滚当前文件；按已提交状态重跑后续阶段，如需重装源数据则从 `02` 开始新一批。

同一批数据重复执行后，记录数和金额必须保持不变。账面原值单位为元，页面字段 `amount_wan` 为万元；借、贷都保留，但账面、预警和八项组成只计算借方。
