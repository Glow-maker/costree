# 成本树代码阅读地图与自学路线

更新时间：2026-06-02

用途：帮助后续接手者，尤其是还不熟悉 Vue3、Java/Spring Boot、Yudao 后端的人，按成本树项目当前真实代码一步一步看懂前端、后端、数据库、接口和运行链路。

本文不替代完整接口文档、数据模型文档和部署文档。它的定位是“导航”：告诉你先看哪里、每块负责什么、改一个功能时要同时关注哪些文件。

## 1. 先建立全局认识

成本树不是独立系统，而是嵌入已有业务中台的一组页面和后端服务。

当前关键路径：

| 类型 | 路径 | 你要知道什么 |
|---|---|---|
| 前端仓库 | `<frontend-root>` | Vue3 页面、路由、接口调用、组件都在这里 |
| 后端仓库 | `<backend-root>` | Java/Spring Boot/Yudao 后端，成本库模块在 `yudao-module-cost` |
| 文档中心 | `<costree-root>/note` | 项目状态、数据模型、接口、部署、风险和变更记录 |
| React/Figma 原型 | `<costree-root>` | 只作为页面和交互参考，最终不直接嵌入 |

先读这 3 份文档：

1. `PROJECT_STATE.md`：恢复当前项目状态。
2. `00-overview/02-全栈边做边学与运行链路说明.md`：理解浏览器、Vite、网关、Nacos、Redis、`cost-server`、MySQL 的关系。
3. 本文：按文件位置阅读前后端代码。

## 2. 当前请求链路怎么走

以打开 `/cost/catalog` 为例：

```text
浏览器访问 /cost/catalog
  -> 前端路由 remaining.ts 找到 src/views/cost/catalog/index.vue
  -> 页面调用 src/api/cost/... 中的函数
  -> 请求 /admin-api/cost/...
  -> Vite 本地代理或业务中台网关转发
  -> 网关通过 Nacos 找到 cost-server
  -> cost-server Controller 接收请求
  -> Service 处理业务逻辑
  -> Mapper 查询 MySQL
  -> 返回 VO 给前端页面展示
```

你以后看任何功能，都按这条链路追。

### 4.1 后端分层怎么理解

| 层 | 文件特征 | 作用 | 新手读法 |
|---|---|---|---|
| Controller | `controller/admin/.../*Controller.java` | 接收前端请求，定义 URL、GET/POST、参数和返回值 | 先看这里，确认接口入口 |
| VO | `controller/admin/.../vo/*.java` | 请求参数和返回给前端的数据结构 | 看字段名，和前端 API 对照 |
| Service | `service/.../*Service.java`、`*ServiceImpl.java` | 写业务逻辑、状态流转、聚合计算、导入导出 | 看“为什么这么查、这么算” |
| Mapper | `dal/mysql/.../*Mapper.java` | 查询 MySQL | 看查询条件、分页、排序、聚合 |
| DO | `dal/dataobject/.../*DO.java` | 对应数据库表 | 看字段和表结构怎么对应 |
| ErrorCode | `ErrorCodeConstants.java` | 成本模块错误码 | 看后端报错语义 |

### 4.2 后端功能模块对应关系

| 功能 | Controller | Service | Mapper / DO | 数据表 |
|---|---|---|---|---|
| 领域-系列-型号树 | `CostModelNodeController` | `CostModelNodeService` | `CostModelNodeMapper`、`CostModelNodeDO` | `cost_model_node` |
| 成本项目列表 | `CostProjectController` | `CostProjectService` | `CostProjectMapper`、`CostProjectDO` | `cost_project` |
| 项目基本情况 | `CostProjectBasicController` | `CostProjectBasicService` | `CostProjectBasicMapper`、`CostProjectBasicDO` | `cost_project_basic`、导入批次表 |
| 工作令基础信息 | `CostWorkOrderController` | `CostWorkOrderService` | `CostWorkOrderMapper`、`CostWorkOrderDO` | `cost_work_order`、导入批次表 |
| 总体展示/单位详情聚合 | `CostOverviewController` | `CostOverviewService` | `CostUnitCostDetailMapper`、相关项目/工作令 Mapper | `cost_unit_cost_detail` 等 |
| 单位字典 | `CostUnitDictController` | `CostUnitDictService` | `CostUnitDictMapper`、`CostUnitDictDO` | `cost_unit_dict` |
| 账面成本明细聚合 | `CostWorkOrderLedgerController` | `CostWorkOrderLedgerService` | `CostWorkOrderLedgerDetailMapper`、`CostWorkOrderLedgerDetailDO` | `cost_work_order_ledger_detail` |
| 预警中心 | `CostWarningController` | `CostWarningService` | `CostWarningRecordMapper`、`CostWarningRecordDO` | `cost_warning_record`、`cost_work_order_ledger_detail` |

### 4.3 推荐后端阅读顺序

如果你还不熟悉 Java，不要从所有类一起看。按下面顺序读：

1. 先读一个最简单的只读接口：`CostModelNodeController`。
2. 再读分页接口：`CostProjectController`。
3. 再读带 CRUD 和状态流转的接口：`CostProjectBasicController` 或 `CostWorkOrderController`。
4. 再读聚合接口：`CostOverviewController`、`CostWorkOrderLedgerController`。
5. 最后读预警：`CostWarningController`，因为它同时依赖目标成本、账面成本、推送/处理状态。

每读一个 Controller，都按这 5 步追：

```text
Controller 方法
  -> 请求 VO / 返回 VO
  -> Service 接口
  -> ServiceImpl 实现
  -> Mapper 查询和 DO 字段
```

## 7. 你自主新增一个功能时按这个流程走

以后不要一上来就写 Vue 或 Java。按下面 10 步做：

1. 确认业务需求：这个功能给谁用，在哪个页面，用来做什么。
2. 确认数据来源：已有表能不能支撑，是否需要新增字段或新表。
3. 先查现有相似功能：优先模仿已有成本树页面和接口。
4. 如果改数据库：同步更新 `schema-mvp.sql`、数据模型文档、部署说明。
5. 写后端：先 DO/Mapper，再 Service，再 Controller/VO。
6. 写前端 API：在 `src/api/cost/...` 新增或扩展接口函数。
7. 写 Vue 页面或组件：只改对应 `src/views/cost/...`。
8. 接路由和菜单：本地先在 `remaining.ts`，正式内网还要配置中台菜单权限。
9. 做验证：前端局部类型检查、ESLint、后端编译、页面或接口验证。
10. 更新文档：项目状态、计划、变更日志、必要时更新接口和数据模型。

## 11. 一个最小练习建议

如果你想开始自己看代码，建议从 `/cost/catalog` 开始，因为它覆盖了最多基础概念：

1. 找路由：`remaining.ts`。
2. 找页面：`src/views/cost/catalog/index.vue`。
3. 找树接口：`src/api/cost/modelNode/index.ts`。
4. 找项目接口：`src/api/cost/project/index.ts`。
5. 找工作令接口：`src/api/cost/workOrder/index.ts`。
6. 找后端 Controller：`CostModelNodeController`、`CostProjectController`、`CostWorkOrderController`。
7. 找表：`cost_model_node`、`cost_project`、`cost_work_order`。
8. 在浏览器里筛选一次，打开 Network 看请求参数。
9. 回到后端 Service 看这些参数怎么被使用。

看懂这一条链路后，再看 `/cost/index` 的聚合逻辑和 `/cost/tree-detail` 的阶段/单位逻辑，会容易很多。
