# 文档结构与维护规范

## 文档目标

本项目文档不是汇报材料，而是后续 vibe coding 的施工依据。每个文档都应能回答一个明确问题：为什么做、做什么、怎么验收、代码或 SQL 应落在哪里。

## 编号规则

- `00-overview`：项目总览和规则
- `10-research`：现有代码、原型、参考模块分析
- `20-requirements`：业务需求和权限需求
- `30-data`：数据模型、枚举、测试数据和 SQL
- `40-api`：接口契约和联调用例
- `50-frontend`：Vue3 页面实现说明
- `60-backend`：Java/Yudao 后端实现说明
- `70-testing`：测试、验收、回归
- `80-deployment`：环境、迁移、上线
- `90-logs`：决策、变更、问题记录

## 文件命名规则

- Markdown 文档使用 `NN-中文主题.md`。
- SQL 文件放在 `30-data/`，命名为 `schema-mvp.sql`、`seed-mvp.sql`。
- 页面级说明放在 `50-frontend/`，按页面拆分。
- 后端生成说明放在 `60-backend/`，按模块或代码层拆分。

## 敏感信息规则

- 账号、密码、Token、密钥、数据库连接信息统一记录在 `80-deployment/00-环境账号与敏感信息.md`。
- 其他文档如需引用账号，只引用该文档路径，不重复粘贴明文密码。
- 本地配置文件、环境变量文件是否可提交，必须先确认 `.gitignore` 和内网安全要求。

## 状态标记

每份核心文档顶部建议维护：

```text
状态：草稿 / 待确认 / 可开发 / 已实现 / 已废弃
负责人：TBD
最后更新：YYYY-MM-DD
依赖输入：TBD
```

## 不确定性处理

- 业务口径不确定：标记【需业务确认】。
- 技术落点不确定：标记【需技术确认】。
- 外网测试临时假设：标记【外网测试假设】。
- 与内网真实数据相关：标记【内网待验证】。

## 生成代码前置条件

生成前端或后端代码前，至少应具备：

- PRD MVP 范围已写清楚。
- 数据表和字段已稳定到可测试。
- 接口路径、请求参数、响应字段已明确。
- 权限点命名已明确。
- 测试数据可以覆盖查询、新增、编辑、删除、导入、导出。
