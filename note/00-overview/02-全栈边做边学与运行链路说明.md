# 全栈边做边学与运行链路说明

状态：持续维护  
更新时间：2026-06-02  
适用范围：成本库 MVP 本地开发、嵌入业务中台联调、后续内网部署学习说明

## 1. 为什么要有这份文档

成本库不是独立系统，而是嵌入已有业务中台。后续每次写代码，都不能只说明“改了什么”，还要解释：

- 这次改的是前端、后端、数据库，还是网关/运行配置。
- 这个文件在系统链路里负责什么。
- 页面请求怎么从浏览器走到 MySQL。
- 出错时应该先看哪个服务、哪个日志、哪个配置。
- 本轮新学到的前后端概念是什么。

本文作为长期学习索引，帮助把“边写代码边学全栈”的过程固定下来。

## 2. 当前本地运行链路

嵌入业务中台开发时，成本库页面的请求链路是：

```text
浏览器 /cost/index
  -> Vite 前端开发服务
  -> 业务中台网关 gateway-server，当前本地端口 38080
  -> /admin-api/cost/**
  -> Nacos 查询服务名 cost-server
  -> cost-server，当前 jt profile 本地端口 38108
  -> Service / Mapper
  -> MySQL 成本库测试库
```

这里有三个容易混淆的点：

- 前端页面地址是 `/cost/...`，这是 Vue 路由。
- 后端接口地址是 `/admin-api/cost/...`，这是管理端接口。
- 网关不直接写死 `38108`，而是通过 Nacos 找服务名 `cost-server`。

## 3. Nacos 是什么，在本项目里做什么

可以先把 Nacos 理解成“后端服务通讯录”。

在本项目里，Nacos 主要有两类能力：

| 能力 | 通俗理解 | 当前成本库用途 |
|---|---|---|
| 服务注册/发现 | 服务启动后登记“我是谁、我在哪个端口” | `cost-server` 启动后注册服务名，网关通过服务名找到它 |
| 配置中心 | 把数据库、Redis、开关配置集中放在平台里 | 内网部署可能启用；当前 `jt` 本地开发重点先用服务发现 |

当前页面报：

```text
Unable to find instance for cost-server
```

意思是：网关知道要找 `cost-server`，但 Nacos 里没有可用的 `cost-server` 实例。

优先排查顺序：

1. `cost-server` 是否启动。
2. `cost-server` 是否使用正确 profile，例如 `jt`。
3. `cost-server` 是否启用 Nacos discovery。
4. `cost-server` 和 `gateway-server` 的 Nacos 地址、namespace、group、账号是否一致。
5. 修改 YAML 后是否重启了 `CostServerApplication`。

## 4. Redis 是什么，在本项目里做什么

可以先把 Redis 理解成“高速临时数据仓库”。

正式成本业务数据不放 Redis，仍然放 MySQL。Redis 通常用于：

- 登录态、Token、用户缓存；
- 框架缓存；
- 临时数据；
- 分布式锁；
- 验证码、消息、任务等中台能力；
- Yudao 平台已有模块依赖的基础缓存能力。

当前成本库配置了 Redis，是因为它嵌入的是完整业务中台生态，不只是一个孤立 CRUD 服务。

需要记住：

- MySQL：保存正式业务数据，例如项目、工作令、成本明细。
- Redis：保存临时状态和缓存，不作为成本数据主账本。
- Nacos：让网关知道 `cost-server` 在哪里。

## 5. 本地排障最小清单

### 5.1 页面提示找不到 `cost-server`

现象：

```text
Unable to find instance for cost-server
```

检查：

```powershell
curl http://127.0.0.1:38108/actuator/health
curl http://127.0.0.1:38080/admin-api/cost/overview/summary
```

判断：

- 如果 `38108` 不通，先启动或重启 `CostServerApplication`。
- 如果 `38108` 通但 `38080` 不通，重点看 Nacos 注册和网关路由。
- 如果修改过 `application-jt.yml`，必须重启后端服务。

### 5.2 页面提示未登录或无权限

检查：

- 当前是否通过业务中台真实登录。
- 前端是否误开 `VITE_COST_MOCK_LOGIN=true`。
- 请求是否带真实 `Authorization` 和真实 `tenant-id`。
- 用户是否有成本库菜单、按钮、数据权限。

### 5.3 Redis 连接失败

检查：

- 本地 Redis 是否启动。
- 端口是否为 `6379`。
- 成本库使用的 database 是否与配置一致。
- 内网是否有 Redis 密码；如有，按部署文档配置。

## 6. 每次写代码时的解释模板

后续每次实现功能，都按这个模板同步解释：

| 说明项 | 要回答的问题 |
|---|---|
| 改哪一层 | 前端 Vue3、后端 Java、MySQL、网关、Nacos/Redis 配置？ |
| 为什么改 | 这个文件在请求链路里负责什么？不改会出什么问题？ |
| 数据怎么流动 | 页面按钮 -> 前端 API -> 后端 Controller -> Service -> Mapper -> MySQL |
| 怎么验证 | 页面怎么点、接口怎么测、数据库怎么查、日志看哪里 |
| 学到什么 | 本轮涉及的概念，例如路由、接口、分页、租户、注册中心、缓存 |

## 7. 学习路线

| 阶段 | 学习目标 | 结合成本库看的内容 | 验收 |
|---|---|---|---|
| A 本地环境 | 知道每个服务为什么要启动 | Vite、gateway、cost-server、Nacos、Redis、MySQL | `/cost/index` 可通过 `38080` 拿到数据 |
| B 一次请求 | 知道页面请求如何到数据库 | `/cost/catalog` 查询链路 | 能说清楚目录树数据从哪里来 |
| C Vue3 前端 | 看懂页面、筛选、分页、弹窗 | `src/views/cost`、`src/api/cost` | 能定位列表/卡片切换和筛选条件 |
| D Java 后端 | 看懂 Controller、Service、Mapper | `yudao-module-cost` | 能知道新增字段要改哪几层 |
| E 数据库 | 知道表和业务对象关系 | 项目、工作令、单位字典、账面明细 | 能区分源数据表和业务展示表 |
| F 权限租户 | 知道登录、租户、角色怎么影响数据 | 菜单、按钮权限、`tenant_id`、数据权限 | 不依赖模拟 `login-user` 做权限验收 |
| G 填报流程 | 知道状态流转怎么保存 | 草稿、提交、待确认、通过、退回 | 能解释轻流程和后续 BPM 的差别 |

## 8. 当前默认约定

- 成本库正式业务数据放 MySQL，不放 Redis。
- Redis 只作为缓存和中台基础设施。
- Nacos 必须用于网关发现 `cost-server`。
- 本地独立调试可显式开启 mock，但嵌入业务中台和权限验收必须走真实登录态。
- 每次功能实现后，必须同步更新相关设计、部署或变更日志文档。
