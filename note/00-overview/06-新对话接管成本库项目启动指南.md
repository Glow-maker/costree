# 06-新对话接管成本库项目启动指南

更新时间：2026-06-12

用途：说明如何让新的 Codex/ChatGPT 对话快速了解并接管成本库项目。本文用于“开启新对话时复制给新 agent”，避免重新口述历史，也避免新 agent 不读文档就直接写代码。

## 1. 接管信息分层

新对话接管时，按三层信息恢复上下文：

| 层级 | 位置 | 用途 | 使用时机 |
|---|---|---|---|
| 快速交接层 | `H:\light\project\costree\.agent-handoff` | 快速恢复当前阶段、下一步、阻塞、待办和决策 | 每次新对话第一步 |
| 项目事实层 | `H:\light\project\costree\note` | 项目长期事实源，包含计划、风险、决策、接口、数据、前后端说明 | 开发前必须读 |
| 原始资料层 | `H:\light\project\costree\docs` | 业务任务书、历史调研、原始输入 | 只有核对原始业务口径时再读 |

原则：

- 不从聊天记录恢复项目。
- 不把 `docs` 当日常接管入口。
- 后续开发以 `note` 为准，`.agent-handoff` 作为快速恢复入口。
- 账号、密码、数据库连接、Token、内网配置不得直接复制给新对话。
- 不要把账号密码、数据库地址、Token 或内网连接信息粘贴到外部对话。

## 2. 同机 Codex 新对话启动 Prompt

如果新对话仍在同一台机器、同一个 Codex 环境，直接复制下面这段：

```text

先不要写代码。请按下面顺序恢复上下文：

1. 使用 agent-handoff：
   python H:\light\project\costree\.agent-handoff\runtime\agent-handoff\scripts\handoff.py resume H:\light\project\costree

2. 阅读这些项目入口：
   H:\light\project\costree\.agent-handoff\START-HERE.md
   H:\light\project\costree\.agent-handoff\CURRENT.md
   H:\light\project\costree\.agent-handoff\TASKS.md
   H:\light\project\costree\.agent-handoff\DECISIONS.md
   H:\light\project\costree\note\README.md
   H:\light\project\costree\note\PROJECT_STATE.md
   H:\light\project\costree\note\PLAN.md
   H:\light\project\costree\note\RISKS.md
   H:\light\project\costree\note\AGENTS.md
   H:\light\project\costree\note\00-overview\04-工程经验与开发约束手册.md

3. 请先输出你理解的：
   - 当前目标

   - 当前未完成任务
   - 当前阻塞

   - 开发前必须遵守的工程约束

确认理解后，再根据我下一条消息执行具体任务。
```

## 4. 按任务补充阅读

### 4.1 前端页面任务

让新 agent 额外读：

```text
H:\light\project\costree\note\50-frontend\
H:\light\project\costree\note\40-api\02-接口字段契约.md
H:\light\project\costree\note\00-overview\03-成本树代码阅读地图与自学路线.md
```

适用场景：

- 迁移或优化 `/cost/index`
- 迁移或优化 `/cost/catalog`
- 做 `/cost/analysis`
- 调整待分配池、预警中心、数据采集页面

### 4.2 后端接口或性能治理任务

让新 agent 额外读：


- 修改分页、聚合、导入导出
- 处理租户、权限、慢 SQL、预警中心

### 4.3 数据库、导入、同步任务

让新 agent 额外读：

```text

```

适用场景：

- 更新 `schema-mvp.sql`
- 设计源表同步
- 处理账面明细导入
- 准备内网部署

### 4.4 项目管理、文档维护、交接任务

让新 agent 额外读：


适用场景：

- 更新风险和决策
- 更新交接文档
- 复刻本项目的文档中心模式到其他项目

## 5. 建议新对话调用的 Skills

| Skill | 什么时候用 |
|---|---|
| `agent-handoff` | 恢复上下文、更新交接状态、收尾 |
| `long-term-project-docs` | 维护 `note` 文档中心、状态、计划、风险、决策 |
| `ui-ux-pro-max` | 优化成本库页面布局和视觉一致性 |
| `build-web-apps:frontend-testing-debugging` | 调试 Vue3 页面、Vite 代理、前端运行错误 |
| `browser:control-in-app-browser` | 在 Codex 内置浏览器验证本地页面 |
| `chrome:control-chrome` | 需要使用用户 Chrome 登录态、插件或真实浏览器状态时验证页面 |
| `superpowers:systematic-debugging` | 遇到 Nacos、网关、登录态、接口异常时做结构化排查 |

## 6. 新对话必须遵守的工作要求

- 先读文档，不要直接写代码。
- 不确定事项标记 `【需确认】`。
- 新需求先补规格，再开发。
- 改接口同步 `40-api`。
- 改 SQL 同步 `30-data` 和 `80-deployment`。
- 改页面同步 `50-frontend`。
- 改后端同步 `60-backend`。
- 风险进 `RISKS.md`。
- 关键取舍进 `DECISIONS.md`。
- 收尾时运行 `agent-handoff close-session` 和 `validate`。

## 7. 开始执行前的确认输出

新 agent 阅读完入口文档后，应该先输出以下内容，而不是立即改代码：

```text
我已恢复项目上下文。当前理解如下：

1. 当前目标：
2. 已完成：
3. 未完成：
4. 当前阻塞：
5. 下一步最小任务：
6. 本轮若开发，需要同步更新哪些文档：
7. 本轮预计验证命令：
8. 仍需你确认的问题：
```

用户确认后，再进入具体实现或分析。

## 8. 常用恢复命令

```powershell

python H:\light\project\costree\.agent-handoff\runtime\agent-handoff\scripts\handoff.py validate H:\light\project\costree
```

收尾时不要直接手改 `.agent-handoff` 生成的 Markdown 文件，应通过更新请求执行：

```powershell
python H:\light\project\costree\.agent-handoff\runtime\agent-handoff\scripts\handoff.py close-session H:\light\project\costree <update-request.json>
python H:\light\project\costree\.agent-handoff\runtime\agent-handoff\scripts\handoff.py validate H:\light\project\costree
```
