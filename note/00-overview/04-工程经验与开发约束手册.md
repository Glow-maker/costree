# 04-工程经验与开发约束手册

更新时间：2026-06-03

用途：沉淀成本库建设过程中已经验证或已经暴露风险的工程经验，作为后续维护、开发、让 AI 生成代码、新需求拆解前的共同依据。本文关注“怎么写才不踩坑”，不替代 PRD、接口文档、数据模型、风险台账和变更日志。

## 1. 使用规则

- 开发前先看本文：凡是新增页面、接口、Mapper、导入导出、聚合统计、权限入口，都先检查是否已有可复用模式或禁止反模式。
- 需求不清先补规格：谁使用、看什么、能操作什么、数据从哪里来、数据量有多大、是否分页、是否涉及权限，写清楚后再开发。
- 工程规则写本文；业务风险写 `RISKS.md`；关键取舍写 `DECISIONS.md`；接口字段写 `40-api`；数据口径写 `30-data`；页面细节写 `50-frontend`；后端细节写 `60-backend`。
- 每次“踩坑后修复”都要判断是否沉淀：如果这个问题下次还可能出现，就补到本文。
- 不确定内容标记 `【需确认】`，不要把猜测写成事实。

每条经验统一用以下字段维护：

| 字段 | 含义 |
|---|---|
| 编号 | 稳定编号，便于在任务、PR、聊天中引用 |
| 场景 | 什么时候适用 |
| 推荐做法 | 后续默认采用的方式 |
| 禁止/慎用 | 已知容易出问题的写法 |
| 参考文件或函数 | 可复用的现有入口 |
| 验收方式 | 怎么证明没有踩坑 |
| 状态 | 已验证、需验证、已废弃 |

## 2. 后端可复用模式

| 编号 | 场景 | 推荐做法 | 禁止/慎用 | 参考文件或函数 | 验收方式 | 状态 |
|---|---|---|---|---|---|---|
| BE-001 | 普通业务列表分页 | 使用 `PageParam`、`PageResult<T>`、`BaseMapperX.selectPage(reqVO)` 和 `LambdaQueryWrapperX` 组合查询 | 禁止 `selectList()` 查全量后 `subList()` 手动分页 | `CostWorkOrderMapper.selectPage`、`CostProjectMapper.selectPage` | 搜索当前接口链路无 `selectList + subList`；真实请求返回 `total` 和当前页 `list` | 已验证 |
| BE-002 | 工作令、待分配池、单位详情等明细页 | 先数据库分页拿当前页业务数据，再对当前页 `workOrderNo` 集合做账面成本聚合 | 慎用前端 `pageSize: 1000` 当作分页；禁止先查全部工作令再聚合 | `CostWorkOrderServiceImpl.getPendingAllocationUnitDetail` | 当前页切换时 Network 只请求当前页；账面聚合参数只包含当前页工作令编号 | 已验证 |
| BE-003 | 同步导出 Excel | 复用分页查询条件，但导出前先查总数并设置最大导出行数，当前默认 5000 行 | 禁止无上限导出真实库全部数据 | 项目基本情况导出、工作令导出接口 | 超过上限时返回明确错误，提示缩小筛选范围 | 已验证 |
| BE-004 | 导入 Excel | 复用中台 `ExcelUtils`、EasyExcel 注解、`MultipartFile` 上传方式，保留导入批次和错误明细 | 禁止导入失败只返回“系统异常”；禁止真实库执行测试 seed | `60-backend/03-导入导出实现说明.md` | 成功数、失败数、失败行号、错误原因可追溯 | 已验证 |
| BE-005 | 草稿、提交、通过、退回轻流程 | MVP 先复用业务表 `status` 字段，按操作校验状态流转 | 禁止前端只改显示状态而不落库；正式 BPM 未确认前不扩流程表 | 项目基本情况和工作令状态接口 | 刷新后状态仍正确；非法状态流转被后端拒绝 | 已验证 |
| BE-006 | 自定义聚合 SQL | 只有 `selectPage` 无法表达清楚时才写 `@Select` 聚合 SQL；必须检查租户、数据权限、索引、真实数据量 | 慎用绕过框架查询的复杂 SQL；禁止未验证租户隔离就上线 | `CostWarningRecordMapper.selectRealtimeWorkOrderWarningPage`、`CostWorkOrderMapper.selectPendingAllocationUnitSummary` | 非 admin、不同租户、不同部门用户联测；慢 SQL 和执行计划检查 | 需验证 |

## 3. 前端可复用模式

| 编号 | 场景 | 推荐做法 | 禁止/慎用 | 参考文件或函数 | 验收方式 | 状态 |
|---|---|---|---|---|---|---|
| FE-001 | 成本库 API 文件 | 新接口统一放到 `src/api/cost/...`，复用中台请求封装和 `PageResult` 结构 | 禁止页面里直接写裸 `fetch` 或硬编码完整后端地址 | `src/api/cost/workOrder`、`src/api/cost/project` | 请求自动带真实登录态；接口路径统一走 `/admin-api/cost/...` | 已验证 |
| FE-002 | 列表页查询 | 使用 `queryParams`、`getList()`、`Pagination`，筛选条件传给后端分页接口 | 慎用一次性加载 500/1000 条后在前端过滤；真实业务明细不允许前端假分页 | `/cost/pending-allocation`、`/cost/catalog` | 翻页、搜索、筛选都会重新请求后端当前页 | 已验证 |
| FE-003 | 成本库局部类型检查 | 成本库改动后执行 `pnpm run ts:check:cost`，避免全仓 `vue-tsc` OOM | 不直接执行 `vue-tsc --noEmit src/views/cost/...` | `tsconfig.cost.json`、`package.json` 脚本 | 不出现 OOM；错误集中在成本库或直接依赖 | 已验证 |
| FE-004 | 本地代理和登录态 | 嵌入业务中台开发默认只配置 `VITE_BASE_URL`，复用真实 token、租户、角色 | 禁止默认注入 `login-user`；`VITE_COST_MOCK_LOGIN=true` 只用于独立 `cost-server` 调试 | `vite.config.ts`、`80-deployment/01-外网到内网迁移说明.md` | Network 不打到错误端口；后端按真实用户处理权限 | 已验证 |
| FE-005 | 页面从原型迁移 | React/Figma 原型只作结构、字段、交互参考，最终按 Vue3 + Element Plus + 中台样式重写 | 禁止把 React 原型作为子应用直接嵌入；禁止保留假数据冒充真实接口 | `50-frontend` 页面设计文档 | 页面数据来自成本库接口；无数据时显示空状态 | 已验证 |
| FE-006 | 成本库页面验收 | 页面变更后至少做局部类型检查、局部 ESLint、登录态页面复核 | 禁止只看静态截图就认为完成 | `PROJECT_STATE.md` 验证记录 | 命令结果、接口状态、页面路径写入状态或变更日志 | 已验证 |

## 4. 数据与聚合约束

| 编号 | 场景 | 推荐做法 | 禁止/慎用 | 参考文件或函数 | 验收方式 | 状态 |
|---|---|---|---|---|---|---|
| DA-001 | 账面明细聚合 | 优先从 `cost_work_order_ledger_detail` 按工作令、阶段等维度聚合；无明细时才用业务表金额兜底 | 禁止把凭证明细全量加载到 Java 内存后循环计算 | `CostWorkOrderLedgerDetailMapper.selectSummary` | 聚合金额与 SQL 手工核对一致 | 已验证 |
| DA-002 | 总体展示、预警、待分配池汇总 | 数据量可能增长的汇总优先 SQL `GROUP BY`，必要时再考虑快照表 | 不提前建每日汇总表；也不长期依赖 Java 内存聚合 | `40-api/02-接口字段契约.md` 聚合接口章节 | 四大领域、单位汇总、预警数量与明细合计一致 | 已验证 |
| DA-003 | 索引设计 | 内网真实数据前检查 `tenant_id`、`deleted`、`project_code`、`work_order_no`、`domain_code`、`unit_name`、`stage_code` 等查询字段索引 | 禁止只用外网小数据判断 SQL 性能 | `RISKS.md` E-002 | 真实数据量下分页和聚合接口响应可接受；慢 SQL 可定位 | 需验证 |
| DA-004 | 源表和业务表关系 | 源系统表保存原始/治理数据，业务表支撑页面和填报，转换规则写入数据文档 | 禁止源表字段一变就直接覆盖业务展示表 | `30-data/01-数据模型-MVP.md` | 数据来源、同步主键、增量字段和异常恢复规则可追溯 | 需验证 |
| DA-005 | 租户字段 | 成本库业务表保留 `tenant_id`，测试库使用真实租户口径构造数据 | 禁止锁死租户 ID；禁止跨租户共享测试数据 | `80-deployment/01-外网到内网迁移说明.md` | 不同租户用户只能看到本租户数据 | 需验证 |

需求拆解时默认遵守：

| 编号 | 推荐做法 | 禁止/慎用 | 验收方式 | 状态 |
|---|---|---|---|---|
| REQ-001 | 所有明细列表默认后端分页 | 慎用前端一次性加载后过滤 | 接口使用 `pageNo`、`pageSize`，返回 `PageResult` | 已验证 |
| REQ-002 | 所有金额字段说明单位 | 禁止只写“金额”不写元、万元或换算口径 | PRD、接口、数据模型至少一处明确单位 | 已验证 |
| REQ-003 | 所有角色差异写清可见页面和可操作按钮 | 禁止只写“按权限控制”但不说明角色差异 | 角色权限矩阵可检查 | 已验证 |
| REQ-004 | 所有未确认口径进入 `RISKS.md` 或需求确认问题 | 禁止只留在聊天记录 | 风险台账或需求确认问题中能找到该项 | 已验证 |
| REQ-005 | 原型截图只说明体验，字段和接口必须单独落契约 | 禁止用截图替代字段清单和接口契约 | 接口字段契约可落地 | 已验证 |

## 6. 反模式清单

| 编号 | 禁止/慎用 | 风险 | 推荐做法 | 验收方式 | 状态 |
|---|---|---|---|---|---|
| ANTI-001 | 后端 `selectList()` 全量查询后 `subList()` 手动分页 | 数据量大后接口慢、内存压力大 | 使用数据库分页或 SQL 分页 | 当前接口链路无 `selectList + subList` | 已验证 |
| ANTI-002 | 前端用 `pageSize: 1000` 作为“够用了”的分页 | 数据超过上限后丢数据或加载慢 | 页面表格接后端分页；下拉字典才允许小批量加载 | 翻页会请求后端当前页 | 已验证 |
| ANTI-003 | 默认代理注入 `login-user` | 覆盖真实中台登录态，权限和租户验证失真 | 默认复用真实登录态，mock login 显式开启 | 默认环境变量下不注入 `login-user` | 已验证 |
| ANTI-004 | 页面展示假数据但没有明显说明 | 业务误以为数据真实 | 无数据时显示空状态，测试数据只进测试库 | 无接口数据时不显示假金额 | 已验证 |
| ANTI-005 | 自定义 SQL 不验证租户和数据权限 | 可能越权查数 | 非 admin、不同租户、不同部门用户联测 | 权限和租户联测通过后再上线 | 需验证 |
| ANTI-006 | 真实内网库执行 `seed-mvp.sql` | 覆盖真实数据 | 真实库只执行建表和必要迁移，测试数据只进测试库 | 部署清单明确禁止 seed | 已验证 |
| ANTI-007 | 修改接口字段但不更新 `40-api` | 前后端联调口径漂移 | 接口变更同步字段契约和联调用例 | 字段契约能找到新增或变更字段 | 已验证 |
| ANTI-008 | 改 SQL 结构但不更新部署说明 | 内网建表遗漏或字段不一致 | SQL、数据模型、部署说明同步更新 | 建表 SQL、数据模型、部署说明一致 | 已验证 |

## 7. 每次变更检查清单

| 类型 | 检查项 |
|---|---|
| 需求 | 是否写清角色、页面、数据源、权限、分页、验收、未确认项 |
| 前端 | 是否放在 `src/views/cost/...` 和 `src/api/cost/...`；是否复用真实登录态；是否执行 `pnpm run ts:check:cost` |
| 后端 | 是否复用 `PageParam`、`PageResult`、`selectPage`；是否避免全量内存分页；是否执行成本模块编译 |
| 数据 | 是否同步 `schema-mvp.sql`、数据模型、部署说明；是否明确租户、删除标记、索引和唯一约束 |
| 接口 | 是否更新 `40-api/02-接口字段契约.md`；是否说明分页、导出上限、权限点 |
| 权限 | 是否确认菜单、按钮权限、数据权限、租户隔离 |
| 性能 | 是否避免全量加载；聚合是否下推 SQL；导出是否有上限 |
| 文档 | 是否更新 `PROJECT_STATE.md`、`PLAN.md`、`RISKS.md`、`DECISIONS.md` 或 `90-logs/02-变更日志.md` 中的对应位置 |

## 8. 后续维护要求

- 新增经验不要写成长篇复盘，优先写成能执行的规则。
- 已废弃规则保留编号，并在状态列标记 `已废弃`，说明替代做法。
- 如果一条经验只适用于某个页面或接口，把详细实现放到对应专题文档，本文只放入口和通用规则。
- 如果规则影响上线风险，同步写入 `RISKS.md`。
- 如果规则代表关键技术取舍，同步写入 `DECISIONS.md`。
