# 分表同步执行顺序

## 首次接入

先选两个真实型号，依次执行并检查结果：

1. `00-使用前总检查.sql`
2. `01-同步型号树-cost_model_node.sql`
3. `02-同步项目-cost_project.sql`
4. `03-同步单位字典-cost_unit_dict.sql`
5. `04-同步单位金额-cost_unit_cost_detail.sql`
6. `05-同步工作令-cost_work_order.sql`
7. `06-同步账面明细-cost_work_order_ledger_detail.sql`
8. `07-重算工作令账面成本.sql`
9. `08-全链路验收.sql`

用同一批数据重跑 `01` 至 `08`，记录数和金额不得增加。

## 定时任务

### 基础数据

建议每日一次，或随源系统基础数据更新运行：

```text
01 型号树
  -> 02 项目
  -> 03 单位字典
  -> 04 预分预控合同/到款
  -> 05 工作令字典
  -> 08 验收基础关联
```

`01` 至 `05` 为全量幂等同步。停用、删除通过映射区的 `deleted/disabled` 传入；本批缺失不视为删除。

### 账面数据

建议按财务源刷新周期运行：

```text
06 账面明细增量同步
  -> 07 工作令账面快照重算
  -> 08 全链路验收
```

增量游标可用 `source_lastmodify` 或源时间戳；防重键为 `source_detail_id`。时间戳仅限定抽取范围，不能作为明细主键。

## 失败处理

1. 脚本报错后执行：

   ```sql
   ROLLBACK;
   ```

2. 停止下游步骤，修正当前脚本顶部的字段映射区，再完整重跑当前脚本。
3. `06` 或 `07` 失败时，不得手工把 `cost_work_order.book_cost_amount` 改成非零。
4. `08` 存在 `ERROR` 时，本批任务判定失败。

## 串行执行

- 同一个租户只能有一个成本同步任务运行。
- 脚本使用事务级 advisory lock，但 DWS 不依赖跨列唯一索引兜底。
- 任一 SQL 返回非零退出码，停止后续步骤。
- 不允许多个工作流分别无条件向同一 `cost_*` 表执行 `INSERT`。

## 批次记录

- 批次开始和结束时间；
- 源表抽取记录数；
- 每张目标表更新数、新增数和总记录数；
- 借方、贷方明细数及金额；
- `08` 的全部验收结果；
- 本次使用的字段映射脚本版本。

## 同步范围

保留填报内容：

- 项目办维护的配套数、阶段、分系统、产品简称、纵向分工；
- 项目办逐单位维护的目标成本、审定金额；
- 研制单位维护的工作令合同、到款、目标、审定、阶段、分系统等字段；
- 已有填报和审核状态。

源同步内容：

- 主业项目树和项目锚点；
- 权威实际核算单位及管理单位映射；
- 预分预控项目单位合同、到款；
- 工作令字典归属；
- 借贷账面明细和可重建的工作令借方账面快照。
