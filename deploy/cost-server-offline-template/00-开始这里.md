# 成本库内网部署包

本目录同时包含成本库后端、完整前端静态资源、PostgreSQL 建库/升级脚本、正式数据接入模板和部署操作手册。数据库脚本分为 PostgreSQL 14+ 和 PostgreSQL 9.2 / GaussDB(DWS) 8.2.1 两套，应用程序和前端资源共用。

## 推荐执行顺序

1. 在部署机运行 `tools/verify-package.ps1` 或 `tools/verify-package.sh`，确认文件完整。
2. 查看 `RELEASE-INFO.txt`，确认后端、前端提交号和数据库结构版本属于同一次发布。
   当前完整包要求结构版本为 `20260820`。
3. 按 `docs/01-部署前准备.md` 完成备份、停机和环境核对。
4. 先执行 `SHOW server_version_num;`，再选择且只选择一套数据库目录：
   - PostgreSQL 14+：使用 `database/postgresql`。
   - PostgreSQL 9.2.x 或 GaussDB(DWS) 8.2.1：使用 `database/postgresql92`，并先运行其中的 `00-dws-precheck.sql`。
5. 在所选目录中二选一：
   - 空库：执行 `01-new-database/costree-cost.sql`。
   - 已有成本库：按 `02-upgrade-existing/README.md` 一次升级到当前版本。
6. 按 `docs/03-后端部署.md` 配置并启动 `cost-server`。
7. 按 `docs/04-前端部署.md` 发布完整前端资源。
8. 按 `docs/06-网关菜单权限.md` 检查网关，并在平台库执行对应方言的四类角色初始化脚本。内网达梦 MQB 首次导入直接按 `database/platform/dm8/00-开始这里.md` 顺序执行，不需要重放历史权限增量。
   然后按 `docs/11-三级权限升级与授权操作.md` 给用户分配唯一成本角色和数据范围。
9. 按 `docs/05-数据链路与首次导入.md` 先同步两个真实型号并完成对账，再扩大范围。
   - PostgreSQL 9.2 / GaussDB 的正式全量快照定时同步优先使用
     `database/postgresql92/03-data-integration/snapshot-upsert/00-开始这里.md`：
     每批只清空中间表，业务表按业务键 `UPDATE + INSERT`，源快照缺失项不自动删除。
     同步前后会校验项目办、研制单位、工作令填报字段和流程状态摘要；发生变化则本批不标记 `SUCCESS`。
   - 只有旧清库流程或灾备演练才允许使用
     `database/postgresql92/03-data-integration/manual-preservation/00-开始这里.md`。
     必须先做完整数据库备份并显式确认；常规同步不得调用该目录。
   - PostgreSQL 9.2 / GaussDB 内网源表字段与标准暂存表不一致时，优先使用
     `database/postgresql92/03-data-integration/manual/README-内网字段映射说明.md`
     及同目录 `00` 至 `08` 分表模板完成首次字段核对；只修改各 SQL 顶部的字段映射区。
10. 按 `docs/07-验收排错.md` 完成接口、页面、金额和重复导入验收。
11. 本次新增字段和页面验收项见 `docs/10-20260728字段与页面变更.md`。
12. 本次四类角色权限升级和越权验收见 `docs/11-三级权限升级与授权操作.md`；双库边界、达梦/PG 脚本选择和日常授权参考 `docs/12-成本树三级权限与双库初始化.md`。两个文件名为兼容既有交付路径保留。
13. `20260819` 升级包含成本分系统字典、阶段多选长度和填报保护校验；分系统字典只位于成本库，不修改达梦中台通用字典。
14. `20260820` 升级包含预警分析、接收人、操作日志和闭环状态机；平台库还要执行预警站内信模板脚本并精确失效权限/模板 Redis 缓存。

## 重要边界

- PostgreSQL 14+ 与 9.2/DWS 脚本不能混用；DWS 现场请使用配套 `gsql`，并先阅读 `docs/09-PostgreSQL-9.2适配.md`。
- 正式库禁止执行所选数据库目录下的 `90-optional-*`、`91-optional-*` seed、演示或清理脚本。
- 已有库不能只执行完整建表脚本，`CREATE TABLE IF NOT EXISTS` 不会给旧表补字段。
- 已有库的结构升级只执行 `02-upgrade-existing/run-upgrade.ps1` 或 `.sh`；`03-data-integration` 不承担结构升级。
- `amount` 的单位是元，`amount_wan` 的单位是万元；页面展示万元。
- 贷方明细可保留用于审计，但账面、预警和八项组成只计算借方。
- 前端必须发布整个 `frontend/dist`，不能只复制成本模块的若干 JS 文件。
- 数据库脚本、后端 JAR、前端资源必须使用本包同一版本，禁止混用旧包。
- 正式包不提供裸业务清库目录；常规同步只能清空中间表。

遇到问题先查看 `docs/07-验收排错.md`，不要直接在正式业务表手写大量 INSERT 或 ALTER。
