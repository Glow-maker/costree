# 旧清库流程手工数据保护

本目录只服务“旧清库重装”或灾备演练，常规 `snapshot-upsert` 不得调用这里的恢复脚本。

执行前必须完成整库备份，并确认当前业务 schema 为 `costree_mvp`、租户编号正确。推荐只使用 `10-旧清库保护过程.ps1`：它会先生成快照并验收，再执行现场提供的旧重装 SQL，最后恢复和复验。

顺序：

1. `01-创建手工快照表.sql`
2. `02-生成清库前快照.sql`
3. `03-清库前验收.sql`
4. 现场旧清库/重装 SQL（本包不提供）
5. `04-清库后恢复.sql`
6. `05-恢复后验收.sql`

`cost_manual_snapshot` 与 `cost_sync_stage` 相互独立；常规“只清空中间表”不会清空手工快照。当前快照同时保护预警任务、接收人、操作日志及其引用关系。未匹配项目、主键冲突或恢复字段不一致都会写入 `restore_exception` 并使流程失败，不能静默跳过。

该保护层不能替代完整数据库备份。

包装器必须同时传入备份确认和清库确认，例如：

```powershell
.\10-旧清库保护过程.ps1 `
  -Database '成本库名' -User '执行用户' -TenantId 124 `
  -ReloadSql 'D:\approved\reload-cost.sql' `
  -BackupVerified `
  -ConfirmBusinessReset I_UNDERSTAND_COST_BUSINESS_RESET
```

`ReloadSql` 必须是已审核、已替换占位符的现场重装脚本。本包不内置或自动执行任何业务表清空 SQL。
