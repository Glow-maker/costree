# 成本库全量快照中间表同步

本目录适用于 PostgreSQL 9.2.4 / GaussDB 8.2.1，也可用于更高版本 PostgreSQL。

核心规则只有三条：

1. 外部源数据每次全量装入 `cost_sync_stage` 中间表。
2. 每次只清空中间表，禁止清空 `cost_*` 业务表。
3. 业务表按稳定业务键先 `UPDATE`、再 `INSERT WHERE NOT EXISTS`。
4. `04` 保存五组手工填报/状态摘要，`07` 复核摘要；任一手工字段被外部同步改变时验收失败。

## 最简执行顺序

首次执行：

1. `01-创建标准中间表.sql`
2. 检查并修改所有脚本中的业务 schema `costree_mvp` 和租户 `124`

每次同步：

1. `02-只清空中间表.sql`
2. 参照 `03-源数据全量装载模板.sql` 将本次完整快照写入六张中间表
3. 确认 `cost_sync_stage.sync_control.load_status='READY'`
4. `04-导入前检查.sql`
5. `05-业务表幂等同步.sql`
6. `06-重算工作令账面.sql`
7. `07-同步后验收.sql`
8. 查看 `08-缺失数据差异清单.sql`

`02`、源数据装载、`05`、`06`、`07` 分别提交，整批不是跨文件原子事务。`ROLLBACK;` 只能回滚当前尚未提交的文件，已经提交的前序阶段不会自动撤销。`05` 完成后状态为 `BUSINESS_SYNCED`，`06` 完成后为 `RECALCULATED`；只有 `07` 验收全部通过后才写入 `SUCCESS`。

失败后按当前状态重跑：装载失败从 `02` 重新开始；`04` 或 `05` 失败时修正中间表后从 `04` 继续；`06` 失败时从 `06` 继续；`07` 失败时可在不改变本批业务数据的前提下修复验收问题并重跑 `07`，否则从 `02` 开始新一批。禁止跳过导入前检查。

使用 `10-最简过程.ps1` 时，未指定 `-SkipClearAndLoad` 就必须显式传入已经完成字段映射的 `-LoadSql`。脚本会在执行 `02` 清空中间表之前拒绝空路径、缺失文件或仍含 `<源系统schema>` 占位符的模板。

## 六张标准中间表

| 中间表 | 来源 | 业务表 |
|---|---|---|
| `stg_unit_dict` | 权威单位字典 | `cost_unit_dict` |
| `stg_model_node` | 主业项目树解析结果 | `cost_model_node` |
| `stg_project` | 主业项目树叶子项目 | `cost_project` |
| `stg_unit_amount` | 预分预控项目单位金额 | `cost_unit_cost_detail` |
| `stg_work_order` | 工作令关联主业项目字典 | `cost_work_order` |
| `stg_ledger_detail` | 工作令凭证明细 | `cost_work_order_ledger_detail` |

中间表使用标准字段。真实内网源表字段只在 `03` 装载模板中映射，后面的检查、同步和验收脚本不再跟随源字段变化。

## 字段所有权

允许外部同步覆盖：

- 单位字典的实际核算单位、管理单位简称、管理单位分类和启停状态。
- 项目的名称、目录树归属、领域、系列和型号。
- 单位金额的合同金额、到款金额和源记录信息。
- 工作令的源主键、编号、名称、实际核算单位和停用状态。
- 账面凭证明细的全部源字段。
- `cost_work_order.book_cost_amount`，但它只能由借方账面明细重算。

禁止外部同步覆盖：

- `cost_project_basic` 全部项目办填报字段。
- `cost_unit_cost_detail.target_cost_amount` 和 `approved_amount`。
- 工作令合同、到款、目标、审定、阶段、分系统、产品简称、配套数、纵向分工和填报状态。
- 成本数据授权表 `cost_user_project_scope`、`cost_user_unit_scope`。
- 预警处理记录。
- 成本分系统字典 `cost_subsystem_dict`。

上述保护由 `cost_sync_stage.manual_field_baseline` 记录同步前已有业务行的逐行摘要，`manual_field_digest` 保存项目办填报、项目状态、单位填报、工作令填报和预警状态五组汇总摘要。同步后只复核同步前已存在的行，因外部快照新插入的基础行不会误报；任一已有行的受保护字段改变或消失都会验收失败。`02` 不会清空这两张表；新批次在 `04` 覆盖当批基线和摘要。

## 与旧清库保护流程的边界

`snapshot-upsert` 是唯一常规入口，不得调用 `../manual-preservation/`。后者只用于已经批准的旧清库重装或灾备演练，必须先做整库备份、生成批次快照、验收 `SNAPSHOT_READY`，并在包装器中输入显式确认字符串。

## 稳定业务键

| 业务表 | UPDATE + INSERT 使用的业务键 |
|---|---|
| `cost_unit_dict` | 租户 + 实际核算单位编码 |
| `cost_model_node` | 租户 + 节点编码 |
| `cost_project` | 租户 + 主业项目编号 |
| `cost_unit_cost_detail` | 租户 + 项目编号 + 实际核算单位名称 |
| `cost_work_order` | 租户 + 项目编号 + 实际核算单位名称 + 工作令编号 |
| `cost_work_order_ledger_detail` | 租户 + 源明细 ID |

源表与单位字典必须用实际核算单位编码关联。业务表保存实际核算单位，页面再按 `manage_unit_name` 聚合成电子所、800所等管理单位卡片。

## 删除与停用

本批中间表没有出现的记录不会被自动删除。`08` 只输出差异清单。

确需停用时，源系统必须在下一次快照中保留该记录并明确传入：

- `source_deleted=1`：逻辑删除来源记录。
- `disabled=1`：停用单位或工作令，但不删除历史账面。

这样可以避免源系统抽取不完整时误删已经填报的数据。

## 金额口径

- 预分预控合同、到款单位为万元。
- 账面原值 `amount_yuan` 单位为元。
- 标准表同时保存 `amount=元`、`amount_wan=元/10000`。
- 借、贷明细全部保留；账面快照、预警和八项组成只统计借方。
