# 全量快照定时同步最简过程

## 每次任务顺序

1. 执行 `02-只清空中间表.sql`。
2. 将六类源数据完整装入 `cost_sync_stage`，可改造并执行 `03`，也可由数据治理工具直接导入。
3. 把 `sync_control.load_status` 置为 `READY`。使用 `03` 时已自动完成。
4. 执行 `04-导入前检查.sql`。
5. 执行 `05-业务表幂等同步.sql`。
6. 执行 `06-重算工作令账面.sql`。
7. 执行 `07-同步后验收.sql`。
8. 保存 `08-缺失数据差异清单.sql` 的结果，人工确认源系统缺失项。

同一时间只允许一个成本同步任务运行。`02`、源数据装载、`05`、`06`、`07` 分别提交，整批不是跨文件原子事务；失败时 `ROLLBACK;` 只能回滚当前尚未提交的文件，已经提交的前序阶段仍然保留。禁止跳过检查继续后面的步骤。

阶段状态依次为 `READY`（装载完成）、`BUSINESS_SYNCED`（`05` 已提交）、`RECALCULATED`（`06` 已提交）和 `SUCCESS`（`07` 验收已提交）。只有 `SUCCESS` 可以作为定时任务成功条件。

## 清理边界

允许清空：

- `cost_sync_stage.stg_unit_dict`
- `cost_sync_stage.stg_model_node`
- `cost_sync_stage.stg_project`
- `cost_sync_stage.stg_unit_amount`
- `cost_sync_stage.stg_work_order`
- `cost_sync_stage.stg_ledger_detail`

禁止清空：

- 所有 `cost_*` 业务表
- `cost_project_basic`
- 项目和单位数据授权表
- 预警记录
- 项目办、研制单位已经填报的字段

## 更新规则

- 同一业务键已存在：执行 `UPDATE`。
- 同一业务键不存在：执行 `INSERT ... WHERE NOT EXISTS`。
- 本批快照缺少旧数据：只输出差异，不删除。
- 源系统明确停用：在本批保留该行并传 `disabled=1`。
- 源系统明确逻辑删除：在本批保留该行并传 `source_deleted=1`。

## 工作流验收门槛

定时任务只能在以下条件全部满足后标记成功：

- `04` 无异常。
- `05` 提交成功。
- `06` 只按借方重算工作令账面。
- `07` 返回 `sync accepted`。
- 同一批快照重复运行后，业务记录数和金额不增加。

## 首次上线建议

1. 先备份六张目标业务表。
2. 只选两个真实型号跑完整链路。
3. 核对实际核算单位名称和编码，不要使用管理单位简称代替。
4. 核对工作令键：项目 + 实际核算单位 + 工作令编号。
5. 核对账面 `amount_yuan` 为元、`amount_wan` 为万元。
6. 核对借、贷都已入明细，但工作令账面和八项组成只统计借方。
7. 两项目通过后再扩大到全量。

## Navicat 操作

Navicat 可以使用。按文件顺序逐个“运行 SQL 文件”，不要一次选中部分语句运行。发生 `current transaction is aborted` 时：

1. 单独执行 `ROLLBACK;`。
2. 查看第一条真正的错误，不要只看后续 transaction aborted。
3. 修正中间表数据或字段映射。
4. 按状态重跑：`READY` 从 `04`，`BUSINESS_SYNCED` 从 `06`，`RECALCULATED` 从 `07`；如需重新装载或改变本批业务数据，则从 `02` 开始新一批。

调用 `10-最简过程.ps1` 执行清空和装载时，必须显式提供已替换源 schema、核对字段映射的 `-LoadSql`。脚本会先校验该文件，再执行 `02`，不会自动运行未修改的 `03` 模板。
