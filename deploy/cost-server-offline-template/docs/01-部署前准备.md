# 部署前准备

## 1. 环境要求

| 组件 | 要求 |
|---|---|
| JDK | Java 8，与现有若依微服务环境保持一致 |
| PostgreSQL / DWS | 推荐 PostgreSQL 14+；兼容 PostgreSQL 9.2.x 和 GaussDB(DWS) 8.2.1，后两者必须使用 `database/postgresql92` |
| Redis | 复用现有平台 Redis，建议为成本服务分配独立 database |
| Nacos | 复用现有注册中心；确认 namespace、group、账号 |
| 网关 | 已有网关需包含 `/admin-api/cost/** -> cost-server` 路由 |
| Nginx | 复用现有前端站点配置，支持 Vue history 回退 |
| SQL 客户端 | DWS 优先安装配套 `gsql`；原生 PostgreSQL 使用 `psql` |

PostgreSQL 9.2 已停止官方维护，只作为内网现状兼容目标。应限制数据库网络暴露、使用专用最小权限账号并保留完整备份，同时制定升级到受支持版本的计划。

## 2. 上线窗口

1. 停止旧 `cost-server`。
2. 暂停所有向成本表写入的数据同步任务。
3. 备份当前 JAR、前端静态目录和 Nginx 配置。
4. 备份成本库，至少包含所有 `cost_*` 表。
5. 记录当前数据库行数与金额汇总，保留回滚依据。

## 3. 必填信息清单

- 成本数据库地址、端口、库名、账号、密码。
- Redis 地址、端口、database、密码。
- Nacos 地址、namespace、group、账号、密码。
- 网关地址及前端站点目录。
- 当前业务租户 ID。
- 内网源表或治理结果的访问方式。

## 4. 包版本检查

运行：

```powershell
.\tools\verify-package.ps1
Get-Content .\RELEASE-INFO.txt
```

正式发布应优先使用 `releaseType=formal`。如果为 `candidate`，说明构建时源码含未提交改动，必须同时保留 `source-state` 中的补丁并经负责人确认。

## 5. 数据库版本确认

连接目标库执行：

```sql
SHOW server_version;
SHOW server_version_num;
SELECT version();
```

- 原生 PostgreSQL 返回 `902xx`，或 `version()` 含 `GaussDB`/`DWS`：只使用 `database/postgresql92`。
- 返回 `140000` 或更高：只使用 `database/postgresql`。
- 其他版本不在本包的已验证范围内，不能直接选择相近目录试跑。
