# 预警分析与闭环处置

本版本新增单位/型号黄红预警分析，以及“项目办推送 → 研制单位反馈 → 项目办退回或闭环”的持久化流程。

## 部署

1. 成本业务库执行第 15 步预警升级，再执行 `20-verify.sql`，结构版本必须为 `20260820`。
2. 平台库执行对应方言的角色权限脚本和 `cost-warning-notify-template-20260820.sql`。
3. 直接 SQL 不会触发中台的 Spring Cache 失效。按平台部署文档精确清理当前租户受影响的 `role`、`menu_role_ids`、`permission_menu_ids`、`notify_template` 键，禁止 `FLUSHDB/FLUSHALL`。
4. 部署同版后端和前端，测试账号退出并重新登录。

## 权限边界

- 项目办仅能处理授权项目；接收人必须是同租户、启用且同时覆盖项目和责任单位的研制单位账号。
- 研制单位只查看授权项目与单位交集，且只有任务接收人能反馈。
- 全局查看、科研部和管理员仅查看审计，Service 层拒绝代办。
- 旧预警记录保持 `LEGACY` 历史；闭环任务永久保留。

## 验收

使用真实项目办、两个研制单位、全局查看、科研部和管理员账号完成：分析对账、候选接收人、部分/全部通知失败、首次反馈并发保护、退回重提、跨项目办闭环、下一周期、实时预警消失后历史追溯，以及所有只读角色写接口 403。
