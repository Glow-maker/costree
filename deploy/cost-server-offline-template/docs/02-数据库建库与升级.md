# PostgreSQL 建库与升级

## 1. 先选择数据库脚本目录

连接目标库执行：

```sql
SHOW server_version_num;
```

| 返回值 | 使用目录 |
|---|---|
| `902xx` 原生 PostgreSQL | `database/postgresql92` |
| `90204` 且 `version()` 含 `GaussDB`/`DWS` | `database/postgresql92`（优先 `gsql`） |
| `140000` 或更高 | `database/postgresql` |

后续命令中的 `<数据库目录>` 必须替换为上表对应目录。两套脚本不能混用。PostgreSQL 9.2 的特别说明见 `09-PostgreSQL-9.2适配.md`。

## 2. 空库安装

PostgreSQL 14+ 空库执行完整脚本。PostgreSQL 9.2 / DWS 空库推荐进入 `02-upgrade-existing` 后运行一键安装脚本：

```powershell
$env:PGHOST='数据库地址'
$env:PGPORT='5432'
$env:PGUSER='数据库用户'
$env:PGPASSWORD='数据库密码'
$env:PGDATABASE='成本库名'
cd .\database\postgresql92\02-upgrade-existing
.\run-new-database.ps1
```

脚本自动优先使用 `gsql`，找不到才使用 `psql`。原生 PostgreSQL 14+ 仍可直接用 `psql` 执行对应目录的完整脚本和验收脚本。

验证脚本应显示结构版本 `20260819`，所有错误计数为 0。空正式库不要执行 seed。

PostgreSQL 9.2 完整建表脚本面向空库且按一次执行设计；如果执行中断，应删除本次创建的空库并重新建库后完整执行，不要在半成品结构上继续逐句运行。

## 3. 已有成本库升级

1. 停止成本服务和同步任务。
2. 完成数据库备份。
3. 进入所选目录的 `02-upgrade-existing`。
4. 运行一键脚本：

```powershell
$env:PGHOST='数据库地址'
$env:PGPORT='5432'
$env:PGUSER='数据库用户'
$env:PGPASSWORD='数据库密码'
$env:PGDATABASE='成本库名'
.\run-upgrade.ps1
```

Linux 使用 `bash run-upgrade.sh`。DWS 可设置 `$env:COST_SQL_CLIENT='gsql'`（Linux 为 `export COST_SQL_CLIENT=gsql`）强制使用官方客户端。脚本固定执行引擎识别、预检查、单事务升级、结构与数据核验。不要把历史零散 ALTER 脚本逐个重放。

Windows 执行 `.ps1` 时要求使用 PowerShell 7（`pwsh`）；Windows PowerShell 5.1 不在本包验证范围内，且可能无法正确解析 UTF-8 中文路径。

## 4. 成功标准

- `cost_schema_migration` 当前版本为 `20260819`。
- 已有库升级必须依次执行 `10-upgrade-existing-to-20260722.sql` 和
  `11-upgrade-existing-to-20260728-project-office-form.sql`、
  `12-upgrade-existing-to-20260817-access-scope.sql`、
  `13-upgrade-existing-to-20260818-domain-scope.sql`、
  `14-upgrade-existing-to-20260819-manual-fields-subsystem.sql`，不能只执行最后一个文件。
- `cost_user_project_scope`、`cost_user_unit_scope`、`cost_user_domain_scope` 三张授权表及其防重索引存在。
- `cost_subsystem_dict` 表、租户内名称防重索引存在，`cost_project_basic.stage_code` 已扩展为 `varchar(255)`，`cost_work_order.vertical_division` 无默认值。
- `20-verify.sql` 中缺列、重复业务键、孤立关联、账面差异均为 0。
- 后端启动后不再出现 `column ... does not exist`。
- 同一批外部数据同步两次，业务记录数和金额不增加。

## 5. 失败处理

- `current transaction is aborted` 只是后续提示，真正原因是同一事务中更早的第一条错误。
- 升级脚本出错会回滚。先执行 `ROLLBACK;`，处理第一条 `ERROR`，再从脚本开头完整重跑。
- 不要为绕过错误直接删业务防重索引。DWS 上这些索引是普通索引，唯一性由同步锁和重复键校验保证。
- 9.2 若提示 `ON CONFLICT`、`ADD COLUMN IF NOT EXISTS` 或 `CREATE INDEX IF NOT EXISTS` 语法错误，说明误用了 14+ 目录。
