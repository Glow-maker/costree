# 后端部署

## 1. 配置

复制配置模板并填写真实连接信息：

```powershell
Copy-Item .\backend\config\cost-server.env.example .\backend\config\cost-server.env
notepad .\backend\config\cost-server.env
```

`application-intranet.yml` 已强制关闭测试登录和本地模拟平台，数据库驱动固定为 PostgreSQL。真实密码只写在部署机的 `cost-server.env`，不要回传源码仓库。

## 2. 启动

Windows：

```powershell
.\backend\bin\start-cost.ps1
.\backend\bin\status-cost.ps1
```

Linux：

```bash
chmod +x backend/bin/*.sh
bash backend/bin/start-cost.sh
bash backend/bin/status-cost.sh
```

生产 Linux 推荐参考 `backend/systemd/cost-server.service.example` 配置 systemd。

## 3. 验证

1. 查看 `backend/logs`，确认无数据库缺列、Nacos 注册或 Redis 连接错误。
2. 在 Nacos 服务列表确认 `cost-server` 实例健康。
3. 直接访问 `http://部署机:38108/actuator/health`。
4. 通过网关访问 `/admin-api/cost/project/page?pageNo=1&pageSize=1`，未登录返回 401/403 也说明路由已通；登录后应返回业务数据。

如果出现 `column ... does not exist`，说明 JAR 已更新但数据库未升级到 `RELEASE-INFO.txt` 标注的结构版本，回到数据库升级步骤，不要手工只补报错的单列。
