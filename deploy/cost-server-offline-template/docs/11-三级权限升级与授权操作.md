# 四类角色权限升级与授权操作

> 文件名为兼容既有离线包路径保留；当前实际为四类普通成本角色。

## 1. 升级顺序

1. 停止 `cost-server` 和成本同步任务，并备份业务库与平台库。
2. 在成本业务库执行对应数据库目录的升级链，必须包含第 12、13、14、15 步：
   `12-upgrade-existing-to-20260817-access-scope.sql`、
   `13-upgrade-existing-to-20260818-domain-scope.sql`、
   `14-upgrade-existing-to-20260819-manual-fields-subsystem.sql`、
   `15-upgrade-existing-to-20260820-warning-workflow.sql`。
3. 执行同目录 `20-verify.sql`，确认结构版本为 `20260820`，三张授权表、成本分系统字典、三张预警流程表和各防重索引均存在。
4. 在中台平台库执行 `database/platform` 下与平台库方言一致的角色初始化脚本。执行前修改租户编号。
   当前中台若为达梦 `MQB` schema，按 `database/platform/dm8/00-开始这里.md` 的 `01`、`02`、`03` 固定顺序执行；客户端必须关闭自动提交，任一步失败立即回滚。
5. 平台 SQL 提交后，按平台部署文档查出受影响角色 ID、菜单 ID 和权限标识，精确删除当前租户的 `role`、`menu_role_ids`、`permission_menu_ids` 以及四个 `notify_template` Redis 键；禁止 `FLUSHDB/FLUSHALL`。然后部署本包后端和前端并清理浏览器旧缓存。

业务库脚本创建数据授权表；平台库脚本创建角色和接口权限。两类脚本缺一不可，也不能互换数据库执行。典型内网结构是：

- 达梦平台库 `MQB.SYSTEM_USERS/SYSTEM_ROLE/SYSTEM_MENU/SYSTEM_USER_ROLE/SYSTEM_ROLE_MENU`：登录账号、角色、接口权限。
- PostgreSQL/GaussDB 成本业务库 `cost_user_project_scope/cost_user_unit_scope/cost_user_domain_scope`：用户可访问的项目、管理单位和科研部单领域。

`cost-server` 通过中台 `PermissionApi`、`AdminUserApi` 获取登录用户和角色，不直接连接达梦平台表。

## 2. 四类角色

| 角色编码 | 用途 | 数据范围 | 填报能力 |
|---|---|---|---|
| `cost_global_viewer` | 领导或全局查看账号 | 全部项目与单位 | 只读，可导出 |
| `cost_research_department` | 科研部账号 | 超级管理员为该账号分配的一个领域 | 只读，可导出；当前无填报和审批 |
| `cost_project_office` | 项目办账号 | 超级管理员分配的项目 | 只维护授权项目的项目办填报 |
| `cost_unit_user` | 研制单位账号 | 超级管理员分配的项目与管理单位交集 | 只维护交集范围内的工作令 |

超级管理员和租户管理员不需要分配上述角色，并可访问“后台管理 -> 成本数据授权”，在当前租户内拥有完整成本管理权限。普通用户只能分配一种成本角色；误配多种角色时系统会拒绝进入成本模块。

四个普通成本角色的若依通用部门数据范围固定为 `data_scope=5`（仅本人）。成本模块的全量、领域、项目和单位范围由独立授权逻辑控制；不要把这些角色改成通用 `data_scope=1`，否则会扩大用户在其他中台模块的数据权限。

## 3. 分配用户权限

1. 登录超级管理员或租户管理员账号，进入 `/system/role`，确认四个角色已存在且处于启用状态。
2. 进入 `/system/user`，选择已有用户，点击“更多 -> 分配角色”，只分配一个成本角色。此步骤走中台页面，不需要执行用户角色 SQL。
3. 打开 `/cost/back/access-scope`，搜索并选择用户。
4. 科研部账号必须选择且只能选择一个领域；项目办账号选择一个或多个项目；研制单位账号必须同时选择一个或多个项目和一个或多个院内管理单位；全局查看账号无需选择范围。
5. 保存后让目标账号重新登录。角色或研制单位任一授权集合为空、单位停用、单位字典无法匹配时，系统按无权限处理，不会默认放开全部数据。

研制单位的项目授权保存到 `cost_user_project_scope`，单位授权保存 `cost_unit_dict.manage_unit_code` 到 `cost_user_unit_scope`。只有项目编码属于授权项目集合，并且工作令中的实际核算单位能通过单位字典映射到授权管理单位时，数据才会开放。

科研部授权保存到 `cost_user_domain_scope`。唯一键为 `(tenant_id, user_id)`，因此每个账号只能存在一条领域授权；授权领域在同租户至少要关联一个活动项目。授权变更由后端物理删除旧记录后插入新记录，不能通过累积逻辑删除记录绕过唯一约束。

## 4. 验收账号

至少准备五个账号逐一验证：超级管理员、全局查看、科研部、项目办、研制单位。

- 全局查看：进入 `/cost/index`；能查看和导出全部数据；看不到新增、编辑、审批、删除按钮。
- 科研部：只能查看和导出所授权领域的数据；直接请求其他领域返回 403 或空数据；看不到新增、编辑、审批、删除按钮。
- 项目办：进入 `/cost/catalog`；只看到分配项目；采集页只显示项目办填报。
- 研制单位：进入 `/cost/catalog`；只看到同时属于授权项目和授权管理单位的数据；成本树、单位页、工作令查询和导出均应用这两个条件；采集页只显示研制单位填报。
- 超级管理员或租户管理员：能访问 `/cost/back/access-scope` 并维护授权。

每个普通账号还要直接修改 URL 或接口参数尝试访问一个未授权项目。研制单位账号至少验证“授权项目 + 未授权单位”和“未授权项目 + 授权单位”两种组合均不可见、不可导出且按 ID 访问被拒绝。正确结果是列表为空或接口返回 403，不能只检查前端菜单是否隐藏。

## 5. 常见问题

- 有角色但目录为空：尚未配置领域/项目/单位范围，或数据所属租户与账号租户不一致。
- 研制单位缺少项目或工作令：先确认 `cost_user_project_scope` 已保存项目，再检查 `cost_user_unit_scope`、`cost_unit_dict` 的核算单位名称、管理单位编码及启用状态，以及单位金额或工作令是否使用相同单位口径。
- 提示成本角色冲突：在系统用户管理中只保留一个成本角色，让用户重新登录。
- 页面按钮仍与旧版一致：确认前端资源、后端 JAR 和数据库脚本均来自同一个 `RELEASE-INFO.txt` 版本，并清理浏览器缓存。
- 达梦提示 `current_database` 无法解析：误把 PostgreSQL 脚本执行到了达梦库；回滚当前事务后改用 `*-dm8-*.sql`。
- 角色已存在但用户无权限：先检查 `/system/user` 是否已分配角色，再检查 `/cost/back/access-scope` 是否保存了项目或单位范围。

长期维护说明见离线包 `docs/12-成本树三级权限与双库初始化.md`。
