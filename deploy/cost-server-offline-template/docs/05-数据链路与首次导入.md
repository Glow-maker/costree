# 数据链路与首次导入

## 1. 总体链路

```text
内网原始/治理数据
  -> cost_integration 暂存层
  -> 单事务校验与幂等更新/插入
  -> cost_* 业务表
  -> 后端聚合接口
  -> 首页、目录、成本树、单位页、组成明细
```

页面不直接查询内网原表。暂存层隔离源字段变化，业务表保持稳定，重复执行同一批同步不会增加记录或金额。

## 2. 各数据从哪里来

| 数据 | 外部来源 | 暂存表 | 成本库表 | 主要用途 |
|---|---|---|---|---|
| 单位及管理单位分类 | 单位字典 | `unit_dict` | `cost_unit_dict` | 管理单位聚合、院内外分类 |
| 领域/系列/型号 | 主业项目树治理结果 | `ads_lc_lshsxm2022` | `cost_model_node`、`cost_project` | 目录树和项目锚点 |
| 工作令归属 | 工作令关联主业项目字典 | `dwd_bd_bfcustomitem_gzl` | `cost_work_order` | 项目、单位、工作令关系 |
| 合同/到款 | 预分预控项目单位数据 | `precontrol_project_unit_amount` | `cost_unit_cost_detail` | 项目单位只读权威金额 |
| 目标/审定 | 项目办按单位填报 | 页面事务接口 | `cost_unit_cost_detail` | 首页、成本树和预警权威金额 |
| 项目补充属性 | 项目办填报 | 页面事务接口 | `cost_project_basic` | 阶段多选、分系统多选、配套数、获取方式、竞价与研制周期等 |
| 工作令补充属性 | 研制单位填报 | 页面事务接口 | `cost_work_order` | 合同、到款、目标、审定、阶段、分系统、工作令简称、配套数和纵向分工 |
| 分系统字典 | 成本管理员维护 | 成本后台 | `cost_subsystem_dict` | 成本模块专用，不依赖 DM8 中台通用字典 |
| 工作令账面凭证 | 财务账面明细 | `dws_bu_pz_pzmx_gzl` | `cost_work_order_ledger_detail` | 账面、八项组成、明细导出 |

## 3. 关键业务键

- 项目：`tenant_id + project_code`。
- 项目单位金额：`tenant_id + project_code + unit_name`。
- 逻辑工作令：`tenant_id + project_code + unit_name + work_order_no`，跨年度仍是一条工作令。
- 账面明细：`tenant_id + source_detail_id`，源明细 ID 必须稳定。
- 账面到工作令：优先使用源工作令主键 `gzlnm -> source_work_order_id`；仅当 `gzlnm` 为空时，才用项目、工作令编号和单位编码/名称兜底。
- 年度只保留在账面明细，不用于复制工作令。

原生 PostgreSQL 使用唯一索引；DWS 使用业务防重索引、串行同步锁和重复键强校验。两种模式都不能只依赖人工维护导入关系。

## 4. 数据口径

- 预分预控合同、到款为“项目 + 实际核算单位”累计万元。
- 单位目标、审定由项目办在 `/cost/collect` 逐单位维护。正式同步保留这两个字段，
  不会用预分预控暂存表中的旧兼容列覆盖。
- 账面源字段 `je` 为元：`amount=je`，`amount_wan=je/10000`。
- 贷方保留审计，但所有账面快照、预警和八项组成只统计借方。
- 八项科目为 `501101` 至 `501108`；不存在的科目金额为 0。
- 管理单位简称和分类来自单位字典。账面明细落库后统一保存工作令的实际核算单位名称，不能把管理单位简称写成核算单位。

## 5. 首次导入操作

1. 根据数据库版本进入对应目录：
   - PostgreSQL 14+：`database/postgresql/03-data-integration`。
   - PostgreSQL 9.2.x / GaussDB(DWS) 8.2.1：`database/postgresql92/03-data-integration`。
2. 首次执行 `00-create-staging.sql`。
3. 把七份 CSV 模板复制到工作目录并填入治理结果；可选的项目办、工作令补充表允许只有表头。
   `precontrol_project_unit_amount.csv` 中 `target_cost_amount`、`approved_amount`
   是旧模板兼容列，正式导入可留空。
4. 设置数据库环境变量并运行：

```powershell
$env:PGHOST='数据库地址'
$env:PGPORT='5432'
$env:PGUSER='数据库用户'
$env:PGPASSWORD='数据库密码'
$env:PGDATABASE='成本库名'
.\load-and-sync.ps1 -CsvDirectory .\csv -TenantId 124 -BatchCode 'PILOT-001'
```

DWS 推荐显式增加 `-Client gsql`。同一数据库同时只能运行一个成本同步批次。

数据治理工作流也可直接幂等维护暂存表，再依次执行 `10-sync-to-cost.sql` 和 `20-verify-sync.sql`。9.2 专用同步脚本使用“先 UPDATE、再 INSERT 缺失行”实现幂等，不依赖该版本尚不支持的 `ON CONFLICT`。

## 6. 两型号试点门槛

- 主业项目树先规范成领域、系列、型号三级，再装载暂存表。
- 两个型号的项目编码必须能贯穿预分预控、工作令映射和账面明细。
- 工作令源主键必须稳定并贯穿工作令映射和账面明细；源账面单位名称可以为空，但工作令源主键为空时必须提供可匹配的单位编码或实际核算单位名称。
- 第一次同步后核对页面和 SQL；第二次用同一批数据同步，记录数和金额必须不变。
- 项目办填写目标、审定后再重跑同一批预分预控同步，目标、审定必须保持不变。
- 对账通过后再扩大到 2000 个项目，不要一次把未治理的全量数据直接写入业务表。

详细字段和脚本说明见所选数据库目录下的 `03-data-integration/README.md`。
