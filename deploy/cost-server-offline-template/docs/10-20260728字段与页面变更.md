# 20260728 字段与页面变更

## 1. 本次数据库变化

`cost_project_basic` 新增三个字段：

| 字段 | 含义 | 维护方式 |
|---|---|---|
| `quantity` | 配套数 | 项目办填报 |
| `product_short_name` | 产品简称 | 项目办填报 |
| `vertical_division` | 是否纵向分工 | 项目办填报 |

`cost_unit_dict.manage_unit_group` 沿用已有字段，增加业务值 `HEAD_OFFICE`：

- 院部：`HEAD_OFFICE`，直接挂在型号下。
- 八部、509所：`OVERALL`。
- 其他分类继续使用 `ASSEMBLY / PROFESSIONAL / FOUNDATION / OUTER`。

工作令查询页和项目办事务接口不需要新增其他业务表。

## 2. 新库与旧库怎么选

- 空库：只执行 `01-new-database/costree-cost.sql`，然后执行
  `02-upgrade-existing/20-verify.sql`。
- 已有库：按顺序执行：
  1. `00-precheck.sql`
  2. `10-upgrade-existing-to-20260722.sql`
  3. `11-upgrade-existing-to-20260728-project-office-form.sql`
  4. `20-verify.sql`

完成标志是 `cost_schema_migration` 存在 `20260728`，且验收脚本错误数均为 0。

## 3. 金额由谁维护

- 合同、到款：预分预控同步，项目办页面只读。
- 目标、审定：项目办在 `/cost/collect` 按实际单位填写。
- 账面：工作令账面明细的借方跨年度汇总，不能人工填写。
- 八项组成：借方明细按 `501101` 至 `501108` 聚合。

正式预分预控同步只更新合同、到款。项目办填过目标、审定后，重复同步不会覆盖。

## 4. 页面验收

1. `/cost/collect` 项目办列表可打开按单位填报弹窗。
2. 合同、到款不可编辑；目标、审定可保存并影响首页、成本树和预警。
3. 研制单位区域左侧为工作令记录、右侧为填报信息，切换项目后只显示该项目工作令。
4. `/cost/work-order-list` 支持服务端分页、组合筛选和详情查看。
5. 成本树中院部位于型号直属最左侧，总体所下只包含八部、509所。
6. 工作令账面、组成和导出只计算借方。

## 5. 回归重点

- 用同一批预分预控数据同步两次，业务记录数不增加。
- 先填写单位目标、审定，再重跑同步，两项人工值保持不变。
- 项目编码、实际单位名称、工作令编号在三个数据源中一致。
- 数据库脚本、后端 JAR、前端静态资源的提交号来自同一个包。
