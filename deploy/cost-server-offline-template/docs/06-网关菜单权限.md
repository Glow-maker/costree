# 网关、菜单和权限

## 网关

现有网关应注册以下路由：

```text
/admin-api/cost/** -> grayLb://cost-server
```

在 Nacos 中确认服务名严格为 `cost-server`。如果直接访问服务正常、经网关 404，优先检查路由和服务注册，不要修改前端接口地址。

## 三级角色与接口权限

先确认平台库使用的数据库方言，再执行且只执行一个脚本：

```text
MySQL 8                 database/platform/costree-access-role-menu-mysql-20260817.sql
PostgreSQL 14+          database/platform/costree-access-role-menu-postgresql-20260817.sql
PostgreSQL 9.2 / DWS    database/platform/costree-access-role-menu-postgresql92-20260817.sql
达梦 DM8（MQB schema）  database/platform/costree-access-role-menu-dm8-20260817.sql
```

执行前把脚本顶部的租户编号 `124` 改成内网实际租户。脚本只创建接口权限和三个成本角色，不会自动给任何用户分配角色。

- 平台库为 PostgreSQL 时，执行 `database/platform/check-cost-permissions.sql`。
- 平台库为达梦 MQB 时，执行 `database/platform/check-cost-permissions-dm8.sql`。

检查结果应为 `OK`。成本业务库和中台平台库可以使用不同数据库方言，例如“成本业务库 GaussDB，平台库达梦”；必须根据脚本实际操作的数据库选择方言，不能根据 `cost-server` 的业务数据源选择平台脚本。

校验不仅要确认 18 个权限点存在，还要确认三个角色均启用、通用 `data_scope=5`，以及角色到成本权限点的映射完整。只看到权限点存在不能作为角色授权完成的证据。

脚本创建三个互斥角色：

- `cost_global_viewer`：全部成本数据只读和导出。
- `cost_project_office`：只看授权项目，仅维护项目办填报。
- `cost_unit_user`：只看同时属于授权项目和授权管理单位的数据，仅维护该交集范围内的工作令。

角色仍在 `/system/role` 管理，用户角色仍在系统用户管理中分配。项目和管理单位范围在超级管理员或租户管理员可见的 `/cost/back/access-scope` 中配置。一个用户只能分配一个普通成本角色；多角色冲突会拒绝访问成本模块。

初始化角色后，给已有中台用户分配角色不需要再写 SQL：进入 `/system/user`，选择用户并执行“更多 -> 分配角色”。平台库中的 `SYSTEM_USER_ROLE` 由中台接口维护。

审批权限已拆分为 `cost:project-basic:approve` 和 `cost:work-order:approve`。不要把审批权限发给普通填报账号。完整操作和验收步骤见 `11-三级权限升级与授权操作.md`。

## 租户

前端请求会携带 `tenant-id`。数据同步脚本中的租户 ID 必须与登录账号所属租户一致，否则数据库有数据但页面查询为空。
