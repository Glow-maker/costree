# 0907 内网操作卡

**已有成本库升级 + DM8 成本权限首次导入。SQL 只做一次；不放进帕科每日任务。**

## 开始前

1. 停成本后端，暂停帕科同步；备份成本库、中台权限/通知表、旧 JAR 和前端目录。
2. 解压整包，运行 `tools/verify-package.ps1 -RequireFormal`（PowerShell）；Linux 可用 `bash tools/verify-package.sh`。必须通过。
3. 打开 `0907首次导入/部署参数生成器.html`，填真实租户 ID、成本 schema、中台 schema。拿不准就先执行同目录两份 `00-识别…sql`，再在中台租户表/现有管理员用户表查看租户 ID。**不填密码、不联网。**
4. Redis 前缀留空仅表示确实没有前缀；若有则包含末尾冒号。核对 system-server 的 Redis 库和 `ignore-caches`，不要误用成本服务自己的 Redis 库。

## 缓存：选一种方式

- 图形客户端：将 SQL 06 **最后一组 CACHE_KEY 列**导出为 `cache-keys.txt`（无表头，每行一键）。连接 system-server 实际 Redis 库，用完整键逐项查找、确认并删除。不存在的键无需处理。
- 命令行：使用同目录 `clear-cost-cache.ps1`。先预览：

```powershell
# 密码仅在本机安全设置 REDISCLI_AUTH，不写入清单或脚本。
.\clear-cost-cache.ps1 -KeysFile .\cache-keys.txt -RedisHost '实际地址' -Database 实际库号 -TenantId 实际租户
# 有前缀增加 -Prefix '实际前缀:'；关闭租户缓存时增加 -CacheMode global；TLS 增加 -Tls。
# 预览核对无误，用相同命令增加 -Execute 才删除。
```

当前源码 `role`、`menu_role_ids` 带租户后缀；`permission_menu_ids`、`notify_template` 属于共享缓存，不带租户后缀。若内网配置不同，必须按实际完整键核对。**禁止 FLUSHDB、FLUSHALL、按 `*role*` 删除。仅重启后端不能替代缓存清理。**

## 账号只在页面配置，不写 SQL

中台「系统管理 → 用户管理 → 分配角色」；普通账号只选一种成本业务角色。管理员在成本「数据授权」`/cost/back/access-scope` 配范围。

| 账号角色 | 配什么范围 / 能做什么 |
|---|---|
| tenant_admin / super_admin | 成本授权管理；预警只审计，不代项目办和单位处置 |
| cost_global_viewer | 无需范围；全局查看、导出 |
| cost_research_department | 单个领域；查看及全周期经费填报 |
| cost_project_office | 授权项目；基础填报、预警推送/退回/闭环 |
| cost_unit_user | 项目＋管理单位交集；工作令填报，被选为接收人后提交预警说明 |

项目办和研制单位提交后仍可修改，不走旧填报审批。预警流程仍是项目办推送 → 单位说明 → 项目办闭环。

## 3D 与每日同步

- 3D 随前端整体发布，不执行 3D SQL，不装 Node.js，不下载外网模型。仅保留经典、3D舱、平台舱；不支持 WebGL 的设备回退经典。
- 前端代理继续指向原网关，保留平台选择页和其他中台入口。不要只复制几个成本 JS。
- 帕科保持已有映射和串行流程：清六张中间表 → 全量装载 → 前检 → UPDATE＋INSERT → 重算 → 验收。**不清成本业务表，不覆盖填报、字典、授权和预警闭环。**
- 上线后用五类账号核对范围、型号比对院内外单位、填报和预警；首次改同步才需再做两批相同快照与源合同修正对账。
- 若需回滚：先停止写入，按本次数据库备份和旧应用整体恢复；不能只换旧 JAR 继续写新结构。
