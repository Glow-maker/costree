# 应用替换：两个服务 + 整个前端

本次包含新中台接口 `/system/cost-role-assignment/*`，只换成本 JAR 不会生效。

1. **成本服务**：用本目录 `cost-server.jar` 替换旧成本服务文件，保留原成本数据库、Redis、Nacos、网关及启动参数。完整包 `backend/bin` 为启动参考，不能覆盖现场配置。
2. **中台服务**：由负责中台运维的人在变更窗口用本目录 `system-server.jar` 替换旧 system-server JAR，保留原服务名、端口、DM数据源、Redis库、Nacos配置、认证/加密配置和启动参数。不要用成本的 `application-intranet.yml` 启动中台服务，不要新增第二个同端口进程。
3. **前端**：将本目录 `dist-prod.zip` 解压到新的临时前端目录，确认根目录有 `index.html`，整体替换原静态站点。保留现场 Nginx/网关代理。不需要安装 Node.js。
4. 启动后检查中台登录及其他既有模块，再检查成本角色分配和数据授权。失败时停写恢复旧应用和原配置，结构变更是否回滚按数据库备份方案决定。

## 配置必须沿用现场原值

交付 JAR 不包含开发、测试或生产环境 profile 文件，基础配置中的固定口令/密钥已改为环境变量。**启动前必须保留原环境完整配置，不能随包带开发环境密码。**

若旧配置只打在旧 JAR 内，先从旧 JAR 的 `BOOT-INF/classes/application-实际环境.yaml`（或 `.yml`）提取到服务器受控配置目录，再沿用原 profile，通过现有运维方式或 `--spring.config.additional-location=file:实际配置目录/` 加载。不要把提取的含密码文件发回外网，也不要覆盖已有外置配置或 Nacos 配置。

成本服务保留原 `mybatis-plus.encryptor.password`、`xxl.job.accessToken`；中台也保留原认证密钥、`mybatis-plus.encryptor.password`、`xxl.job.accessToken`、`fw` 等已有配置。不生成新密钥，不改变现有加密数据的密钥。包内 JAR 外部参数清单见完整包 `backend/config/EXTERNALIZED-CONFIG.txt`。

中台 JAR 是当前分支完整服务构建，不是一个可叠加安装的插件。需要按中台发布流程安排替换，并回归已有模块；本包未连接真实内网环境验证。更新应用代码不需要在 DM 中直接执行写入 SQL。
