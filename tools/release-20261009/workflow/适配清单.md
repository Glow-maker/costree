# 现场唯一适配区

只改 `config.json`、`source-mapping.sql`、`source-readiness.sql`。不要改 templates 中手填字段白名单、判重/事务/主键/验收逻辑来绕过报错。

## 部署参数

| 项 | 填写与确认 |
|---|---|
| business_schema | 实际业务 schema；不是数据库名/JDBC URL，不推定为 public |
| stage_schema | 独立中间层，建议 `cost_sync_stage_v20261009`；不与原全量流程共用 |
| source_schema | 当前连接可读取的源快照或镜像 schema，与业务/中间层分离 |
| tenant_id | 实际租户，示例 124 不是所有环境的默认真值 |
| source_mapping_confirmed | 核对以下字段、金额单位和稳定ID后改为 true |
| batch_code / snapshot_tag / expected_rows | 仅 SQL 多节点人工/平台参数版本填写；daily-runner 自动生成/统计 |

## 六个源映射块

原映射来自既有已交付 snapshot-upsert 模板，以下表名/字段仍是现场须核对的模板，不保证内网源字段同名。

| 中间表 → 业务表 | 源模板 | 必须核对的来源/粒度 |
|---|---|---|
| stg_unit_dict → cost_unit_dict | unit_dict | accounting_unit_code 为实际核算单位编码；accounting_unit_name 为实际名称；manage_unit_* 为管理展示映射；inside_group/inside_institute 与 disabled 的真值约定 |
| stg_model_node → cost_model_node | ads_lc_lshsxm2022 | lshsxm_xmnm 为稳定节点编码；parent_xmnm 是真正父节点内码，不能用名称猜；lshsxm_js 1/2/3 对应 DOMAIN/SERIES/MODEL，名称 lshsxm_xmmc |
| stg_project → cost_project | ads_lc_lshsxm2022 第3级 | lshsxm_xmbh 是主业项目编号；lshsxm_xmnm 对应 MODEL；先确认第3级确实是成本业务项目粒度，不能将普通上级目录当项目 |
| stg_unit_amount → cost_unit_cost_detail | precontrol_project_unit_amount | 一条稳定 source_record_id 对应项目+实际核算单位的一份累计金额；contract_amount/income_amount 单位万元；不能把24年/26年同名单位累计值盲加 |
| stg_work_order → cost_work_order | dwd_bd_bfcustomitem_gzl | id 是稳定 source_work_order_id；zyxmcode 对应项目编号；accountorgcode 对应实际核算单位；cusitemcode 工作令号；同一逻辑工作令不能简单按年度重复生成 |
| stg_ledger_detail → cost_work_order_ledger_detail | dws_bu_pz_pzmx_gzl | ysnm 是跨批次稳定源明细ID，需确认跨年度也唯一；xmbh 项目、dwbh 核算编码、gzllb 工作令号；je 是元；jzfx 借贷；所有年度明细与借贷都装载 |

源查询修改时保留 `-- BEGIN SOURCE ...`/`-- END SOURCE ...` 标记、INSERT 中间表及其列清单，只调整 SELECT 表达式与 FROM/WHERE 来源。源字段不存在时不能为通过检查随意填 0、空串或每次生成新ID。稳定键默认不能超过目标128字符；超长应先做经过评审的显式映射，不允许截断碰撞。

本方案不依赖更新时间水位。源端确实没有可靠修改时间时，可将对应时间表达式明确写为 `NULL::varchar(64)`；没有删除标识时，可将 `source_deleted` 表达式明确写为 `NULL::varchar(16)` 并记录“源未提供删除语义”。这表示未知，不表示已确认未删除；本批缺失记录仍只报告、保留待核查。稳定记录键不能采用这种空值处理，也不能每次重新生成。真实存在的删除/冲销标志不得为了通过检查改成 NULL。

`source-readiness.sql` 必须返回一行 `{snapshot_tag text, is_complete boolean}`：真实源发布批次、六相关数据集是否完整发布。没有上游发布标记的系统，需要先由数据平台提供可证明的冻结/完成机制，不能用 `SELECT NOW(), true` 冒充。默认占位使任务失败，不触及业务数据。

发布标记的约定也要确认：下一批开始改源表之前，先把“完成”撤销；六个数据集全部发布后，才更新批次并置完成。不能保留“昨天完成”标记同时逐表覆盖今天的数据。外表/跨库视图即便能由同一连接 SELECT，也不自动共享本库事务快照，必须由数据平台保证发布期间不可变，或先落到本库的一致镜像。

## 源字段与手填字段归属

| 对象 | 此流程允许写 | 明确保留 |
|---|---|---|
| 项目目录/项目 | 外部名称、领域/系列/型号归属、树父ID | 原项目ID、项目填报/审核/预警状态、手工归属、阶段、备注 |
| 项目基本情况 cost_project_basic | **完全不写** | 整行，包括人工用户、平台/系列、价格、目标、审定、阶段、备注等 |
| 项目单位金额 | source_record_id/source_update_time、合同、到款；新增外部基本记录 | 目标、审定、单位账面、分项成本、备注、逻辑删除状态 |
| 工作令 | 外部编号/名称、项目/实际单位归属、disabled；派生 book_cost_amount | 单位填写合同/到款/目标/审定、阶段、分系统、简称、数量、纵向分工、填报状态、备注、逻辑删除状态 |
| 账面明细 | 按稳定源明细ID写外部凭证和元金额、关联信息 | 既有业务ID；不存在按名称简单合并或每批重建ID |
| 权限、预警处理、分系统字典 | **不写** | 原数据与引用 |

## 代表性人工核对

首次隔离运行后，核对至少：一个普通单位、一组同名历史异码、跨年度工作令、负金额/冲销、数笔小额元凭证、已有人工目标/审定/备注、已有逻辑删除记录。相同快照重跑不新增重复；修改源合同/到款仅更新对应白名单列；同名异码模糊匹配应阻断而非任选一条；人为在最终事务制造失败时业务与手填内容保持原值。真实字段与人工保护审计参见本次 `manual-field-audit.md` 交付附件。

## 将来若改成真正水位增量

当前不启用水位。至少先确认：每种源稳定主键；可靠且精度明确的更新时间/版本；同一时间戳的稳定排序键；迟到/回填的重叠窗口；删除或冲销事件；跨源同批发布完成信号；先完整初始化；回放去重；“目标事务提交成功后才推进”的持久游标及失败恢复。未定义这些条件前，不能把 `WHERE 更新时间 > 上次时间` 加上就称为可投产增量。
